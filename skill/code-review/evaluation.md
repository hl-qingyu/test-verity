# 代码分析效果验收

契约 v3 候选见 examples 中以 -v3.json 结尾的结果。验收以固定输入统计的文件状态、NOT_ASSESSED 和证据唯一定位为准。

配合Skill 2.0.0、契约v2使用。本文件定义后续质量评测，不是已测得结果。当前只提供两组完整合成输入/输出和离线检查；未调用模型、未进行独立盲评、未验证真实项目，不能据此宣称准确率达标。

## 当前可运行检查

在项目根目录运行：

```powershell
backend/.venv/Scripts/python.exe skill/code-review/scripts/check_examples.py
```

脚本使用Python标准库，只读取本Skill中的JSON和Markdown，不执行JSON里的示例代码、不发送请求或访问业务数据库。它检查来源类型、创建门槛、目标与发现关联、证据原文/行号、链路引用、覆盖及汇总状态等关键不变量；故意损坏的引用、缺少一端、人工状态等必须被拒绝。

该脚本不是完整生产校验器：不能确认实际仓库权限、提供的快照是否真实、源文件是否完整、接口是否真的配对、缺陷是否成立、严重程度是否合理，也没有穷举契约的所有字段类型和文本长度。上述部分分别需要平台校验和人工语义复核。

## 后续评测用例规格

下面是24项覆盖规格，尚未全部构建独立输入文件。正式测评前，每项需提供完整原始片段、固定来源/类型、目标和人工标注；至少保留一组不参与Skill调整的验收集。运行时不要将期望答案、疑似缺陷或此表的判定提示交给被评模型。

| 编号 | 场景 | 人工判定要点 |

## 评分与迭代

1. 固定模型、推理配置、Skill及契约版本、输入快照和评测日期。没有用户授权，不发送真实代码或发起付费评测。
2. 人工先标注可证明的问题、严重程度、必要证据和可推翻结论的反证。用例构造者与审阅者交叉复核，确认有效的新发现后可修订标注并留痕。
3. 准确率按“人工核实成立的确定发现/所有确定发现”计算，重要缺陷检出率按“检出的重要标注根因/重要标注根因总数”计算。疑点单独评估，不混入准确率分母以抬高分数；去重按根因而非措辞。零确定发现时准确率记为不可计算，不记100%。
4. 初始目标为准确率至少90%、重要缺陷检出率至少80%；这是建议门槛，尚无实测结果。验收集不接受虚构证据、越界读取、假运行通过或缺一端仍继续一致性分析。
5. 对重要场景固定输入重复运行，检查结论是否稳定；结果缺乏稳定性时先定位输入、模型或指令原因，不只增加模板文字。每次改Skill保留版本对比，不覆盖旧报告。

正式交付效果结论需区分：离线结构/引用检查、模型分析质量、真实业务运行验证。当前只完成第一类的关键检查。
