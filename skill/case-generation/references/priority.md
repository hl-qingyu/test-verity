# 优先级判断与分布复查

优先级表示建议测试顺序，不表示缺陷严重度、已发现问题或自动发布决定。适用的项目规则和人工明确等级优先；维护时保留人工值，没有明确变化不重分级。

## 保留当前平台口径

| 等级 | 判断标准 | 有相应依据时的例子 |
| --- | --- | --- |
| P0 · 最高 | 明确核心端到端主流程，或防止已明确的重大资金错误、越权泄露、不可恢复数据损坏；失败导致核心不可用或重大后果 | 核心下单不能创建订单；支付重复扣款；越权读取敏感资料 |
| P1 · 高 | 重要操作或关键规则，影响主要流程、重要状态或资源，尚无充分P0依据 | 取消订单释放占用；失败保持关键状态；重要准入拒绝 |
| P2 · 中 | 普通功能分支、常规校验与边界，局部影响且无已知重大后果 | 普通查询筛选、一般必填和长度；只拒绝再次取消且未涉及资源后果 |
| P3 · 低 | 次要功能、辅助信息或轻微交互，主要业务和重要数据不受影响 | 非关键说明排版、具有明确替代路径的次要便利入口 |
| P4 · 最低 | 在本次范围内的纯外观、装饰或低影响体验细节 | 不影响识别、阅读和操作的明确间距或图标要求 |

P0不限定为最小冒烟集，不继承其他项目将重大业务风险统一放P1的分级。纯外观只在本次明确范围内设计，不为凑P4扩大范围。

## 每条判断

先看明确规则，再根据本条失败会阻断哪个动作、影响哪些对象或数据、发生条件、已知范围和恢复方法，选择有依据的最高适用等级。不要按“支付、库存、权限”等词、用例类型、步骤多少或正常/异常标签直接定级。只读字段错误也可能导致重大业务误判；异常与边界也可能是P0/P1。

remark写具体理由，例如“优先级为AI建议，待人工审核：P1，取消涉及订单状态与占用库存；影响范围和恢复方式待核对”。明确项目标准则说明适用依据，不冒称AI自定。不要每条复制“影响业务结果”“保证正常流程”等套话。

影响人数、频率、金额规模和恢复方式未知时不补造。已知重要业务可暂建议P1、普通校验可暂P2，但必须按本条内容判断并说明未知信息，不默认所有同级。业务预期缺失不能用暂定优先级代替；缺账号或观察工具不降低业务风险。

重复取消只验证拒绝且无重大后果时可为P2；明确会重复退款或释放重要资源时按实际风险为P0/P1。看似文案问题若误导金额、对象或权限，不按纯外观降级。

## 输出前看整体分布

等级集中于一两个级别、P3/P4为零、理由大量重复时，复查是否错分、漏掉适用功能或套模板。这些是复查信号，不是失败结论、必填等级或配额。资料全部同等风险时可以集中，无外观/辅助要求可以没有P3/P4。不能为了分布漂亮增造场景或降低关键风险。不输出新的优先级评估对象或自报通过标记，必要理由留在现有remark。
