# 粒度、等价输入与语义去重

## 一条确定路径

每条用例写清对象、角色、必要条件、关键输入、实际操作顺序和相关结果。互斥状态、角色、输入类别或可替代路径分开；同一次操作的状态、资源与记录等相关断言可分行保留。多步与预期不按行数配对，不强制单结果或一个展示字段一条。

多个结果是否属于同场景，检查是否共享必要准备、输入、角色路径与业务动作。不同权限、数据、时点和恢复方式不能为了减少数量合并。独立任务不能通过“并且”塞入一条；同一路径的多个相关断言也不机械复制整套步骤。

## 分清四种复用

1. **重复来源**：相同当前业务规则在多页、正文和批注出现，合并支持来源，不因来源多而增加用例。
2. **输入等价**：同字段、同规则、同路径的普通有效区间可选代表，前提是结果与风险确实等价。上下界及相邻值、零、空、非法类别、不同格式和用户指定覆盖不据此删除。
3. **候选重复**：对象、角色与视角、有效必要条件、关键输入、动作、时点、结果和恢复等价时合并；标题、编号和功能结构不是判据。
4. **共享执行**：相同准备与操作可以承载相关断言，但共享操作不证明不同断言或分支重复，不新增执行场景表或改变平台测试结果口径。

## 条件删除与差异判断

逐项删除附加条件，检查是否影响入口、分支、输入、结果或归因。没有影响的背景条件不用于制造独立用例。但条件子集和相同结果本身不能证明冗余：不同字段非法值、边界、拒绝原因、时间点或权限即使同样被拒绝，也可能必须保留。

明确不同处理路径、组件或用户指定回归即使同结果也可保留，note简述具体区别，不虚构“实现变体”理由。无法判断等价时先回到本次依据；不要静默删掉覆盖，也不把自己未完成的去重判断包装成产品待确认。

输入中的空格、大小写、全半角和数字可能是验证目标，不能当排版归一化消除。例如“A B”和“A  B”只有当前规则证明等价且本条不验证差异时才能选代表。不同数据、故障方法、准备引用版本或外部配合不得只凭前置文字相同而合并。

## 去重后的反查

合并时保留全部有效支持来源，检查原有角色、分支、输入和断言均被承接。只改变标题或分类不能消除重复，也不能创造独立价值。选定已有用例的REUSE同样要覆盖必要条件、动作及全部相关断言，只有来源仍有效或标题接近不够。

按业务功能和路径组织输出方便审阅，不靠编号顺序或交付条数证明完整；不设固定降幅、数量下限或80/500条目标。无法完成的部分在UNFINISHED说明具体内容，其他有效用例保留。
