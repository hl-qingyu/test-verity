# 用例生成分段输出契约（待接入草案）

首次调用仍提供完整固定资料和全部规则。平台随请求给出带稳定 `segment_id` 的目标清单；每个目标说明业务范围及相关来源引用。目标决定本次输出范围，模型仍应结合全部资料判断跨目标的业务规则。模型不得自行新增目标；发现范围缺口时写入相应段的 `notes`。

输出采用逐行 JSON（NDJSON），每个目标输出一个完整对象，以换行结束并立即开始下一段；不得使用代码围栏、外层数组或段间说明。每段沿用现有 `cases / notes / complete` 的结构和业务校验，另加 `type` 与平台提供的 `segment_id`：

```jsonl
{"type":"segment","segment_id":"store","cases":[],"notes":["当前依据不足，需补充保存失败规则。"],"complete":false}
{"type":"end"}
```

`complete` 仍表示模型声明的业务覆盖情况；即使为 false，完整且通过校验的段仍可保存。`end` 仅表示本次输出结束，不代表每个目标均已返回，也不代表业务覆盖完整。平台对照目标清单判断哪些段已保存。

平台按完整行做结构、范围、来源、权限和引用校验，通过后立即持久化待审阅建议。保存以任务和段 ID 去重，建议身份在重发时保持稳定。断流时保留已保存段、原始结果及审核状态；截断行或未通过校验的段不得入库，未返回的段继续标为待补。

手动重发使用原任务的完整固定资料和对应版本的 Skill，只提供用户选中的待补段作为输出目标；已保存段不可重发或覆盖。独立记录每次调用及诊断，保留项目权限和本人 AI 配置，不自动重试。旧契约任务及历史报告继续按原版本处理。

验收至少覆盖：两段合法结果后第三段断流；重发第三段后原两段与审核状态不变；错段、重复段、无结束换行的截断段均不能覆盖已保存结果。先用模拟流验证。
