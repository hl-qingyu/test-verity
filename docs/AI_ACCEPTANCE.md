## 详情到指标的映射

| 模块 | 认可 | 明确误报 | 忽略／不适用（已处理但不判错） | 仍待核对 |
| --- | --- | --- | --- | --- |
| 需求分析 | NEEDS_INFO已确认待补充、RESOLVED已解决 | 无对应状态 | NOT_APPLICABLE不适用 | PENDING待确认不计已处理 |
| 代码／变更影响 | CONFIRMED已确认、RESOLVED已处理 | FALSE_POSITIVE误报 | 无对应状态 | NEEDS_EVIDENCE需补证据；PENDING仍未处理 |
| 用例分析问题 | 已确认待处理、已解决，或实际应用成功 | 原流程未单列，不推断 | 不适用 | 待确认且尚未应用为未处理 |
| 用例生成候选 | 实际已应用、已复用 | 原流程未单列，不推断 | 已忽略 | 需人工确认／应用失败；草稿或排队不计认可 |
| 变更回归建议 | ACCEPTED已采纳作为可用 | 不套误报口径 | REJECTED不采纳作为不可用 | DEFERRED暂缓、PENDING待审阅不进可用率分母 |

“认可”表示人工已确认问题有价值或采用最终设计；人工修订后采纳同样认可，因此不等于AI原稿准确。原“人工有效率”改名“人工认可率”，原“人工验收进度”改为“人工处理进度”。历史详情已明确处理的记录直接纳入仅读统计，无需补填一遍。保存人工草稿不等于入库，后台成功才计用例采纳。

## 公式

核心条目仍分别为需求风险、代码发现、变更影响／风险／历史复核、生成NEW/UPDATE候选、用例分析findings；人工补写不进AI分母，回归建议与说明单列。设N总条目、V认可、F明确误报、D忽略／不适用、Q待核对、U未处理，N=V+F+D+Q+U。

| 指标 | 计算 |
| --- | --- |
| 人工处理进度 | (V+F+D)/N |
| 人工认可率 | V/(V+F+D)，不叫原稿正确率；D不被当作误报 |
| 已认可风险／问题／影响／用例数 | V；尚无明确处理样本显示未知 |
| 明确误报数 | 仅详情明确标误报F；无对应状态不推断 |
| 依据核对率 | 明确已核对依据的条目数/有明确核对结果条目数。生成只取已保存evidenceChecked；用例分析只在经依据核对的草稿实际应用成功后计已核对；代码／变更NEEDS_EVIDENCE计待补证据。其余没有明确记录保持未知，不用AI自报证据状态代替人工 |
| 重复建议数 | 原详情未单列重复原因，保持未知；不从“忽略”或自由文本猜重复，也不新增一次评价 |
| 关键遗漏／人工基准覆盖率 | 按可选原范围清单计数；覆盖只认关联条目当前详情已认可，没有清单显示未知 |
| 用例采纳率 | 原生成NEW/UPDATE候选中实际已应用数/候选总数，原始REUSE/RETIRE与人工草案不纳入；保持已有口径 |
| 回归建议可用率 | 详情ACCEPTED数/(ACCEPTED+REJECTED)数 |
| 修订建议采纳率 | 原始明确修订建议中实际NEW/UPDATE应用成功数/明确建议总数；复用不充当修改成功 |

比例保留一位小数，展示实际分子／分母。0分母显示“—”；同记录同key一次，跨记录不按标题或目标去重；需求同一报告去重、生成只读已保存完成批次，失败尝试不造样本。项目汇总不受近期8条或原分析菜单筛选影响。全部项目按模块分别累加所有项目和记录的分子、分母，不平均百分比：如项目甲1/2、项目乙1/8，汇总为2/10=20.0%。没有结果的项目不额外制造指标样本。

## 实现与数据保护

沿用modules/acceptance及迁移36的analysis_acceptance表，无新表／迁移／AI／Worker。sources以SQL标量投影原条目、详情当前处理状态／明确依据标记及成功映射，service在管理员权限内仅读计算。全部项目按五类来源批量投影，不逐个项目循环调用接口或下载原文；可选清单以project_id/module/record_id关联，并核对source_token，跨项目同名条目或基准不会错绑。前端复用公共HTTP，按范围校验响应project_id（含null），切换范围时卸载旧汇总并取消请求，旧响应不能覆盖新范围。原详情操作无签名或事务修改，不增加跨模块写依赖。

管理员GET `/api/projects/{project_id}/analysis-acceptance`及项目成员GET `/{module}/{record_id}`分别提供项目汇总和单记录指标。POST仅允许保存可选清单／范围说明；逐条items由服务端按当前详情重新核对，试图从此接口另设判断或详情已变化时409 acceptance_use_detail。project_id/module/record_id、source_token、revision、Origin及基准关联照常校验。

已有analysis_acceptance.state.items及history不删除，但旧独立逐条评价不再覆盖现有详情统计；详情状态回退时计数同步回退，原清单／审计保留，关联基准仅当前认可时计覆盖。原报告变化使旧清单不再冒用，历史仍可追溯。当前详情审计是处理决策的来源，不另造一次认可写入。

两份总HTML同步仅一个详情处理入口和可选清单，保留浏览器已有数据。先前独立验收流程及原稿质量口径已被本次简化决定替代；验证和运行状态见SESSION_CONTEXT最新条目。
