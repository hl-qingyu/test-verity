# 用例生成（正式接入）

## 现行规则

新建用例生成固定资料、规则和现有用例范围，由本人配置执行。候选先人工审阅，确认入库后逐条提交。旧 v2 记录仍可审核和入库，重试与导入提示新建生成。原生续聊可保存候选轮次和独立审核历史。

以往阶段和验证记录见 [历史记录](archive/CASE_GENERATION_HISTORY.md)。

旧版契约 v2 的记录仍可查看、审核和入库。旧版批次重试和旧版结果导入会提示新建用例生成，已有记录保留固定输入、Skill 和审核历史。

原生终端显示、尺寸回放、增量重连和历史对话缓存由五类分析共用。用例生成的候选轮次继续经原审核入库流程处理。[CLI 实施契约](AI_CODEX_CLI_IMPLEMENTATION.md)

## 页面状态缓存

同一登录会话和当前项目内，从菜单离开后返回「用例生成」，恢复所选生成记录、已展开的列表范围、历史记录搜索词和侧栏开合。进入后重新读取记录列表和所选报告，记录消失时回到当前列表首条。项目概览的定向跳转独立处理。切换项目、退出或刷新页面后从默认状态开始。缓存只保存在页面内存，审核勾选、弹窗和报告正文每次进入重新初始化。

## 界面文案（现行）

生成报告、历史对话及候选保存区精简常驻说明，保留实际来源/范围、计费动作、状态、校验问题和审核入口。终端不再常驻展示固定资料、缓存、权限拦截或报告覆盖机制；这些实现约定记录在本文。保存区只显示轮次、有效候选数、原始JSON和保存/审核操作；存在校验问题时才显示问题提示，0问题不单列。文案精简不改变保存、权限、模型调用或审核规则。

## 原生CLI续聊结果转待审阅（2026-11-17）

CLI 续聊正常结束并返回可解析的生成 JSON 后，后台立即保存为当前对话的待审候选，终端可继续输入。历史对话内的“查看或手动保存 CLI 结果”保留轮次选择、原文预览和手动保存入口。旧轮次以及格式破损的候选可点“手动保存到当前对话”。已保存的轮次可直接“审核本轮候选”。自动与手动保存共享源结果去重。普通解释以及失败或中断的轮次不触发自动保存。complete=false 不阻止保存已有合法建议。

保存只在原CaseGenerationRun下追加独立候选轮次，不新建对话；原批次报告、CLI历史、原响应、Skill快照及各轮人工处理均保留；不自动合并多个轮次、不应用用例、不调用模型。复用delivery/原contract结构与引用校验：有效项继续审阅，问题项在“冲突与待澄清”保留原文和所有重复值，原始完整JSON另存私有候选文件。原来源权限/哈希在保存时复核，目标/当前版本在后续原审核应用流程复查。

已保存的对话候选在审核区查看。顶部仅显示当前生成的排队、运行或需处理的非成功状态。历史批次的状态、诊断和人工重试入口在“完整报告”查看。候选结构问题在“冲突与待澄清”处理，范围完成情况按原报告展示。

只允许同一项目内本次原生执行发起人读取/保存，沿native_terminal.generation的真实执行所有者规则；客户端仅传结果摘要ID，不传文件路径、输入、报告或Skill。结果ID绑定thread/turn/时间/原文哈希，后端从服务器绑定私有会话读取；轮次后追加普通问答不改变已有ID。同一对话内按源结果幂等，不重复保存同轮候选；各轮采用独立建议/问题/证据命名空间；复用请求UUID保存不同结果拒绝，来源身份/角色/逻辑删除继续检查。溯源保存在已有metadata.native_results与该轮保存审计（原run/batch/thread/turn/哈希/操作者/时间/请求UUID），没有新表、字段或依赖。

新增GET `/{run_id}/terminal/results`、GET `/{run_id}/terminal/results/{result_id}`及POST `/{run_id}/terminal/results/{result_id}/save`；请求使用原同源/身份能力及公共HTTP。审核区的“候选轮次”默认全部轮次，可手动筛选单轮。保存后留在当前历史对话，点击“审核本轮候选”才切换到该轮。切换轮次时清除勾选和筛选。建议、澄清、校验问题和原始报告按轮次展示，各轮按原“批量审核入库”逐条提交；全记录人工处理历史保留。各轮沿用真正生成时的旧Skill快照，不用当前磁盘新版替换；退出CLI并不自动启用2.1.2或重做模型分析。

候选轮次使用原CaseGenerationBatch保存，标记NATIVE_MANUAL_REVIEW，禁止作为模型批次收费重试；免费修正和重新校验继续使用原入口。首次生成已自动捕获同一原文时，只补充来源标记，不重复保存或改写报告。新增Alembic 20261117_45只更新批次表及相关字段中文注释，无物理结构变化，模型注释同步。

旧实现产生的独立候选副本仅在原输入、来源绑定和Skill相同、原文哈希一致、没有人工处理/应用/采纳评估记录时归回原对话；不满足则拒绝自动归并。旧副本逻辑归档并记录目标轮次，原输入、报告及私有原文保留。后续候选直接追加原对话，不再创建副本。


2026-11-17：用例生成Skill升至2.1.2，契约3不变。明确有依据且仍可完成的设计、拆分、补断言/补读工作必须先继续完成，不用“模型尚未处理/本次设计未完成”作为UNFINISHED提前收尾。业务缺决定只隔离最小分支，其他明确场景完成后仍可因BUSINESS_QUESTION返回false；真实不可用资料/无法恢复的读取等阻碍仍如实保留。主文件与反查/依据/粒度/角色参考规则同步消除相反表述，evaluation增加六组合成判据；旧输入/Skill快照及运行中的原生会话不改写，不自动重跑或新增收费请求。

终端恢复还原尺寸：会话DTO提供实际启动行列数，旧历史先按该尺寸解释原始光标控制，再适配当前区域，避免宽度变化产生行首残留字。新执行另在私有sizes.enc.jsonl按原始输出帧位置记录初始尺寸和后续resize，沿原密钥加密；原ANSI日志不改写，回放按位置应用尺寸。旧历史没有记录的中途resize不能补造，本次实际93按原126列恢复的残留行验证已消失。

首次恢复遮罩复用统一generation-spinner旋转图标；已有减少动态效果偏好时遵循主题规则。长日志按不超过约256Ki字符/2048片段的有界页传输，前端在同页内合并连续文本写入，保持原始顺序/内容及cursor语义，避免5万片段逐次细碎绘制。恢复期间不向PTY回传尺寸，ready及历史解析完成后才适配/显示最新画面。


## 用例生成原生CLI历史对话与画面缓存（现行）

原生CLI直接复用“历史对话”页的既有主区域，不再显示独立“CLI工作区”按钮或弹窗。原生批次开始/重试成功后进入该历史页；API记录仍使用原平台聊天。引用、功能标签和记录导航保留，原生CLI沿用整条原会话，不因此另建平台模型问答。后续聊天不自动覆盖生成报告。

当前页面首次进入后保留同一个xterm实例、解析后的画面、待处理输出和WebSocket连接；返回报告只隐藏并禁用输入，后台新增输出继续进入缓存。重新进入仅复查权限/当前执行，直接显示底部，不从头下载或解析历史。父级回调改变不重建终端。缓存按用户/项目/记录及实际执行epoch隔离；切换记录/项目、退出登录或离开用例生成页面时释放，不把私有画面存入localStorage/IndexedDB。刷新页面后首次仍需从服务端恢复。

使用 Responses API 的历史对话沿原后台队列发送，回复完成后随该轮保存经过白名单过滤的请求诊断。

WebSocket重连携带已接收帧cursor，沿原权限校验仅取新增输出；新执行/重试epoch变化清空旧画面和cursor。首次或冷恢复期间在后台解析历史，收到ready并完成xterm异步写入后滚至底部一次显示，后续可向上查看。历史回放/隐藏状态不回传按键和旧终端查询应答，只有当前可见且有效的活动会话可输入；Esc返回生成报告不取消CLI。显式结束/取消按钮仍沿原服务。


## 大文件和内嵌图片的阅读组织（2026-11-17）

原始input.json完整提供，不代表模型已完整看见单次工具输出。此次真实会话中，旧工具一次打印含图片Base64的完整JSON，原生CLI明确提示约580734 token输出被截断；之后“继续”轮未再读取工具，只沿历史输出部分候选。完整输出107149字符、155条候选但complete=false；正常turn完成不等于范围完成，也不是平台30分钟超时。

公共`integrations/cli_reading`在任务目录内从原input.json生成不可变reading-v1-<原件SHA256>阅读目录：按messages原角色、顺序和content序号列出完整正文；正文文件最多4096个Unicode字符，目录按6144字节分页，多层目录同样有界。保留原input.json与其全部业务内容，不概括、不筛选，不创建多个独立业务任务/调用。新增文件只是本次原生任务的阅读表示，全部仍通过原标准MCP filesystem读取，无自定义MCP协议、文件读取工具或任意命令接口。

有效PNG/JPEG/WebP/GIF内嵌data URI按原字节还原为本目录图片，正文只将该URI换成本地文件名；目录记录原message/part、字符位置、URI前缀、字节哈希和替换路径。相同图片只存一份，所有出现位置分别保留。非法或不支持转换的URI（包括现有SVG文本）原样留在正文，不能静默删图。原生`input_image`附件仍走原始原生附件传输；新增内嵌图片沿标准read_media_file和functions.exec的image内容转发进入视觉输入，不能只打印Base64冒充看图。不请求外部图片链接。

新指引要求从目录逐项读取正文和图片，一次输出一个小文件文本；遇truncated必须重新分次读取，不能把被省略的内容当作已读。继续未完成业务时先核对目录、补读缺失资料，再完成设计与反查；可继续完成时不因为内容多或上一轮已有部分候选而提前交卷。原Skill业务待澄清、真实上下文或工具限制仍如实保留，不强制把complete改true，不添加平台自动续发/自动收费重试。

原生TUI首次启动从实际保留的input.json构建阅读表示；后续恢复校验源文件及阅读文件的SHA256，直接复用既有目录，不再解析整包JSON、拆分正文、解码图片或写入临时阅读目录。文件摘要清单沿后端现有主密钥认证加密保存，原子落盘，绑定原件SHA256；篡改文件、伪造清单、缺文件或符号链接明确失败。旧目录首次升级仅完整比对一次并补清单，不改写既有阅读文件。仍另写按内容哈希命名的指令文件，不覆盖旧instructions.txt、固定Skill、原始输入或原生历史；非交互大文件入口复用同一能力，小文本/API通道不变。

恢复同一CLI会话的指引明确要求利用历史中已完整读取且当前仍可用的内容、阅读记录及已有成果，不因打开/恢复会话要求从头重读，也不要求每次重新读目录；仅补读未读、被截断、压缩后缺失或当前问题需要核对的部分。首次分析仍须完整阅读范围，缓存存在不等于模型读过。恢复本身不发送新分析，下一轮由用户输入发起；不伪造持久化的语义阅读完成状态，不保证模型一定不按需复读。关闭弹窗重开只恢复显示连接。

此改进解决已复现的整包文本截断和内嵌图未作为视觉资料提供的问题；不能以目录存在、工具调用或假provider结果证明模型已理解/覆盖全部业务。实际任务仍依原候选/引用/结构校验及人工审核；不自动重跑旧分析或把后续聊天覆盖生成报告。没有新依赖/数据库表/字段/迁移、工具权限或等待时限。


## 受限原生 CLI 网页终端

数据库短时故障不会终止已运行的CLI；其完整回答先按调用预留UUID加密落盘。数据库恢复后，原批次读取同一结果，继续原候选保存、结构/项目/引用校验和待人工审核流程，不重新调用模型。调度器断连期间不领取新任务，原执行仍占用预留。Worker重启可交付已完整落盘且仍属于当前任务的结果；没有完整结果的已退出进程不能自动续跑。用户取消及权限/配置变化仍在恢复保存前复核。
选择本人 CLI 配置后，点击“开始生成”直接运行网页可见的同一个原生 CLI。平台在原生成批次入队前绑定私有会话目录，Worker 领取原批次、自动传入完整固定资料和 Skill 并提交生成问题；不另建独立终端任务，不要求用户再输入一次。开始和人工重试成功后进入本记录的“历史对话”，CLI嵌入既有主区域；返回生成报告后可从原“历史对话”入口重新进入。Windows ConPTY + xterm.js 原样传输 CLI 的 ANSI 画面和按键，不解析成平台操作标签，不改写普通对话文本。浏览器通道仍检验本机 loopback Origin、登录会话、项目和本次执行发起人；关闭网页不取消生成，没有打开浏览器也能执行完成。

返回报告与Esc都只隐藏历史对话，后台进程和当前轮次继续执行；Esc不传给CLI。同一页面保留终端实例及画面缓存，并接收后台新增输出；重新进入只复查访问和当前执行，直接显示缓存末尾。断线后通过已接收帧cursor补齐新增输出；新执行/epoch改变或页面销毁时清空缓存，刷新后首次需恢复历史。首次恢复期间禁用输入并隐藏逐帧绘制，ready且xterm异步解析完成后显示底部一次；旧终端查询不回传。需要停止任务仍使用显式取消/结束进程按钮。

固定资料的文件读取改用 MCP 项目现成的 filesystem 服务（版本2.3.0，Node.js 24以上），直接启用其只读模式及本次目录限制；不再接入自写 verity_input 工具，不定义字节偏移/分片协议。完整 input.json 与 Skill 快照保留。旧会话恢复时仅新增工具更新说明文件，不改原文或重发旧分析；标准工具与CLI管理文件读取及原生上下文处理。

后端从同一 CLI 的 app-server 通知取得本次生成轮最终完整 agentMessage，不从终端画面抓文字或把过程说明拼成报告。只有该轮正常完成才能交回原 execution 流程，保存原始候选并执行结构、项目及引用校验；失败、中断或空结果不当作完整报告。校验通过只保存待人工审核的生成建议，不自动应用用例。终端“取消生成”调用原记录取消接口，排队和预算仍使用原生成任务。API 方式保持原流程；已经在跑或排队的旧非交互任务不自动切换，也不自动重试历史失败。

原生 `!命令` 不继承模型工具的沙箱边界，因此不能仅靠禁用模型 Shell 工具。现行实现让真实 CLI TUI 通过带随机凭证的私有 loopback RPC 代理连接本任务的 `codex app-server --stdio`，不直接连接无过滤的执行器。模型Key只给app-server，TUI仅获本次代理凭证。代理按固定0.166.0协议白名单允许对话/历史/只读状态，拒绝用户shell、命令执行、额外进程、文件系统读写、插件安装、MCP重载和配置写入等操作；未知方法拒绝。线程创建/续接/轮次重新固定本任务 cwd、never审批和verity只读权限，禁止外部路径、权限配置、动态工具及客户端权限授权响应。普通消息里的 `!`、`!=`、换行和终端键不做字符过滤。

当前固定版本在 `!命令` RPC 被拒绝后会退出本轮TUI。页面明确提示“本机命令已拒绝，未执行”，用户可手动继续CLI恢复已保存问答，不自动重发模型请求。新会话/恢复均必须经过同一代理；代理失败时不回退到直接本机CLI。试用用户配置 `AI_CLI_TERMINAL_USER_IDS` 不设置时按既有项目记录发起人权限开放；显式空列表禁用，非空列表可进一步限制账号。这个开关只控制受限终端，不授予本机命令权限，不再要求用户放开完整命令能力。

原生历史恢复后的普通追问允许发送。固定版本 TUI 会在 turn/start 附带默认协作模式的 developer 模板，代理丢弃客户端模板、保留后端固定 Skill 和权限，不将整条普通消息误判为越权；其他协作模式不开放。普通追问“继续分析”不等于本机命令。主生成失败后续接窗口显示“对话进程运行中”，只说明进程存在，不表示原生成仍在分析或报告已保存。

终端进程与分析轮次分别显示：根据原生 app-server 的 turn/started、turn/completed 记录当前轮正在分析、已完成、已失败或已中断；CLI仍存活时，终态标明“CLI等待输入”，不把进程RUNNING当作模型还在分析。失败原因直接使用既存私有RPC错误，常见上游流未完成即断开以中文说明。轮次状态先于历史ANSI回放发送，并在变化时更新，不依赖进程状态变化；长历史回放不会延后失败提示。不因此重发问题或覆盖报告。

RPC 失败、轮次结束的状态/原始错误、显式中断和策略拒绝原因脱实际 Key 后加密保存在本次执行的私有 *.rpc.enc.jsonl；不记录普通提问正文或任意 RPC 参数，不写公开应用日志。旧执行没有采集的原因不补造。启动请求被服务端拒绝时结束本次候选等待，失败和中断分别标记，均不自动重试。
