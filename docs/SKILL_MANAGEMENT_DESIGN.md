## 1. 功能范围

保留现有「配置与管理 → Skill 管理」入口和 `/skills` 路径。只管理已经接入的五类分析 Skill，不新建业务 Skill，也不增加导入、试跑、发布审批、项目绑定、启停或版本管理工作台。

所有有效登录用户可查看；只有有效的平台管理员可修改。项目负责人、项目成员及职责标记不授予修改权限。

建议采用平台统一规则：每个分析模块对应一个 Skill，所有项目共用。切换项目不会切换内容；管理员保存前明确提示「影响所有项目的新分析」。本页面不要求先选项目，仍沿用登录和账号状态校验。

## 3. 页面设计

采用「Skill 列表 → 文件树 → 文件内容」三栏。左侧选 Skill，中间展示其真实目录结构，右侧查看所选文件，保持平台现有白色面板、浅绿选中态、主题按钮和间距。只显示真实内容及必要说明，不放模拟分析结果、统计卡片或无实际用途的操作。

```text
Skill 管理
查看各分析模块使用的方法与约束

┌──────────────┬──────────────────────┬─────────────────────────────┐
│ 需求分析     │ 用例生成             │ SKILL.md       [修改内容]   │
│ 用例生成 ←   │ ├ SKILL.md ←         │ 分析说明 · 参与当前AI调用   │
│ 用例分析     │ ├ contract.md        │ 底版 2.0.4 · 修订 0         │
│ 代码分析     │ ├ evaluation.md      │                             │
│ 变更分析     │ ├ legacy-contract.md │ [阅读] [原文]               │
│              │ └ examples/          │ 所选文件的完整内容          │
│              │   ├ compact-input…   │                             │
│              │   └ compact-report…  │                             │
└──────────────┴──────────────────────┴─────────────────────────────┘
```

- 默认选中第一项及其 `SKILL.md`；切换加载对应文件清单，慢请求返回不能覆盖后来选中的 Skill 或文件。
- 文件树显示实际文件名、子目录和用途；`SKILL.md`、`contract.md` 优先，其余按目录与名称排列。只显示真实存在的文件，不给缺少示例或脚本的 Skill 补造空节点。
- 内容标题显示所选文件的相对路径、用途，以及「参与当前AI调用 / 参考文件 / 历史约定」；不能把看得见的所有文件都称为模型已读取。
- Markdown 提供「阅读 / 原文」切换：阅读模式正常显示标题、表格等，原文显示完整文件，包括元信息。`SKILL.md` 有在线修订时默认展示有效修订，明确标注来源，不能展示旧底版却让AI调用新版。
- JSON 默认格式化为便于阅读的代码文本，可切换原文；代码和其他文本按原文显示。格式化只影响展示，不改写文件；无法解析的 JSON 显示原文及格式提示，不伪造内容。
- 单文件独立显示完整内容，不把整个目录合并成一篇正文。长文不截断；代码块横向滚动限于块内，长单词和表格不得撑宽整页。
- 同目录 Markdown 相对链接定位文件树中的对应白名单文件，支持目录展开与选中；链接目标未纳入可读文件时明确提示。禁止越过 Skill 根目录，不自动打开外部网址或加载外部媒体。
- HTML 作为文本处理，不执行原文中的 HTML/JS；Python 等脚本只展示源码，不提供执行或试跑按钮。
- 窄屏将 Skill 列表和可收起的文件树置于内容上方；当前路径、完整内容和管理员操作均可访问。复用主题控件，覆盖目录展开、键盘选择、焦点、加载、空目录、文件缺失及读取失败状态。

### 文件类型与实际用途

| 文件 | 展示方式 | 当前用途 | 本期修改建议 |
| --- | --- | --- | --- |
| `SKILL.md` | Markdown 阅读及完整原文 | 分析方法，参与当前AI调用 | 仅管理员可修改正文 |
| `contract.md` | Markdown 阅读及完整原文 | 输出约定，参与当前AI调用 | 只读，随程序校验逻辑维护 |
| `evaluation.md` | Markdown 阅读及原文 | 行为验收说明，不自动发送AI | 只读参考 |
| `examples/` 下 JSON | 格式化文本及原文，保留目录 | 合成输入/输出示例，不是业务报告，不自动发送AI | 只读参考 |
| `legacy-contract.md` | Markdown 阅读及原文 | 旧格式说明，供历史流程参考，不进入新任务指令 | 只读参考 |
| `scripts/` 下源码 | 代码原文 | 开发校验脚本，不自动发送AI、不执行 | 只读参考 |

本轮实际文件结构：需求分析有两份示例；代码分析有评估、四份示例及校验脚本；变更分析有评估及三组双JSON；用例生成有评估、旧契约及多组双JSON；用例分析目前只有 `SKILL.md` 和 `contract.md`。均按真实清单展示，数量后续以读取结果为准。

`__pycache__`、`.pyc` 等缓存不列为 Skill 内容；`skill/packages/` 是跨版本分发压缩包目录，不混入某个当前 Skill 的文件树。本期不增加压缩包浏览、下载或执行能力。未来目录新增资料或图片时需先登记支持的安全预览类型，未支持文件显示名称和「暂不支持预览」，不能当空文本或自动发给AI。

显示范围与调用范围分别登记：本期新分析实际拼接 `SKILL.md` 和 `contract.md`，其他文件虽可查看也不会因此进入模型输入。今后若正式分析增加引用文件，需同步调用清单、完整快照及用途标签；不能靠 Markdown 链接或管理员正文里的文件名扩展调用范围。

「底版」表示随程序维护的文件版本，「修订」表示管理员在线保存次数。初始为修订 0；保存后为修订 1、2……，不要求管理员手填技术版本号。页面可显示最近修改人和时间，默认不增加历史浏览页。

以上为待审阅布局，不将旧总原型的「导入 Markdown / 编辑与试跑 / 已发布」当作本次已确认方案。后续修改原型须同步总 HTML 和仓库副本，再对照开发及视觉验收。

## 4. 管理员修改流程

选择 Skill → 选择 `SKILL.md` 查看当前内容 → 点击「修改内容」→ 在主题弹窗编辑 Markdown 正文 → 预览 → 保存确认 → 保存成功后展示新内容。

本期建议只允许编辑 `SKILL.md` 分析说明正文，选中参考文件、契约或脚本不显示编辑按钮。模块名称、固定标识、目录、底版元信息和输出契约由程序维护，不能在页面改输出字段、契约版本或执行权限。原正文中的业务方法和表达要求可以修改；权限、结构和人工审核仍由平台强制执行，不能靠文字取消。多文件展示不意味着允许任意改文件、新增、删除或重命名。

编辑弹窗包含：Skill 名称、当前修订、正文编辑/预览页签、取消和保存。保存确认明确：「保存后供所有项目的新分析使用；已准备、执行中和历史分析保持原内容。」不自动发起模型测试。

- 未修改时保存禁用；正文为空或超出明确平台文本上限时显示应用内校验提示，保留草稿。文本上限与现有任务输入上限协调，不把它当模型容量。
- 预览仅渲染当前草稿，不表示已保存，也不表示 AI 效果已验证。
- 保存期间锁定重复提交和关闭；失败留在弹窗，保留输入并显示原因。
- 取消、切换或页面内离开有未保存修改时用主题弹窗确认；刷新/关闭保留系统离开保护。
- 保存请求带加载时取得的当前内容标识。另一管理员已保存、程序底版已变化或契约已变化时返回冲突，不覆盖；提供重新加载，丢弃草稿前再次确认。
- 保存响应丢失时查询当前标识和正文哈希，确认是否成功；不能因客户端超时直接追加另一份修订。

| 操作者 | 查看全部允许展示的Skill文件 | 修改正文 | 修改输出契约或模块绑定 |
| --- | --- | --- | --- |
| 平台管理员 | 可以 | 可以 | 本页面不提供 |
| 项目负责人 | 可以 | 不可以 | 不可以 |
| 普通用户 / 项目成员 | 可以 | 不可以 | 不可以 |
| 未登录、账号停用或删除 | 不可以 | 不可以 | 不可以 |

普通用户不显示编辑入口。修改接口同时复用管理员身份依赖，并在 service 保存事务内重新确认操作者有效且 `platform_role=ADMIN`；管理员打开弹窗后被降权，保存应返回 403。前端隐藏按钮不能替代后端权限。

2026-10-14用户移除模板管理后，管理方案的规则优先级为：平台固定权限和必要结构 → Skill → 本次关注点，不再设计模板绑定入口。修改 Skill 不扩大资料读取、Git 写入、代码执行、自动审核或个人 AI 配置权限；历史任务固定指令保持原件。

生效时间以任务固定 Skill 快照为界：

| 情况 | 使用内容 |
| --- | --- |
| 保存后新准备 / 新创建的分析 | 当前有效正文与匹配契约 |
| 已准备、排队或执行中 | 该任务已经固定的内容 |
| 已有失败任务的固定输入重试 | 原任务内容，不替换为最新修订 |
| 用户希望按新版重新分析 | 明确新建关联分析，再固定当前内容 |
| 历史报告、已审核用例、已有对话 | 原数据保持，不自动重写或重跑 |

独立对话有各自的固定系统提示，本期不把它们加入五类 Skill 列表，不借正文修改顺带改写对话策略。已有对话继续按所属模块规则处理。

## 6. 内容来源与最小持久化建议

项目根目录 `skill/<功能目录>/SKILL.md` 及同目录 `contract.md` 继续作为受代码审查的程序底版。页面和分析共用同一加载入口，不能一边展示文件，一边调用另一份内容。

建议在线修改保存为一张追加式修订表 `skill_content_revision`，不通过接口直接写源码文件。该表保存对固定底版的正文修订，不引入任意 Skill 上传目录或第二套功能目录。

| 字段 | 含义 |
| --- | --- |
| id | 修订记录标识 |
| skill_key | 五类固定 Skill 标识之一 |
| revision | 该 Skill 的递增修订号，与底版语义版本分开 |
| base_version / base_sha256 | 编辑所依赖的底版版本与完整文件哈希 |
| contract_version / contract_sha256 | 配套只读输出契约版本与哈希 |
| skill_text / contract_text | 保存时的完整有效文件与契约快照，便于追溯 |
| instructions_sha256 | 按调用方实际拼接方式得到的指令哈希 |
| created_by / created_at | 实际修改管理员及带时区时间 |

同一 Skill 的修订号唯一；保存串行核对当前标识，内容完全相同不增加修订。首改前保存原底版快照；后续只追加，不覆盖原修订。使用最新匹配底版/契约的修订；无修订使用文件底版。时间不是并发版本标识。

程序升级导致底版或契约哈希变化时，不静默沿用旧在线正文，也不悄悄回退默认值。管理页明确提示「底版已变化，需管理员核对」；新分析准备拦截，已固定任务保持。管理员核对新底版后重新编辑保存，形成新修订。升级交付须事先处理该状态，不制造无提示的全平台阻塞。

数据库修订存储是本方案新增建议，尚未建表；完整 Skill 功能文件仍按根目录约定维护。后续确认实现时同步架构、模型、Alembic 迁移和每个表/字段的真实中文注释。默认不做项目私有版本、发布状态或自动回退。

## 7. 与已有分析接入

本轮核对的现有入口：

| 模块 | 当前读取位置 | 接入时需要处理 |
| --- | --- | --- |
| 需求分析 | `backend/app/modules/requirements/risk_analysis_execution.py` 的执行流程直接读取两文件 | 将完整指令固定在任务进入队列前；Worker 使用快照；不能只固定资料 |
| 代码分析 | `backend/app/modules/code_analysis/sources.py::skill_snapshot()` | 文件为 2.0.1，当前快照标签写死为 2.0.0，需统一元信息与实际内容 |
| 变更分析 | `backend/app/modules/change_analysis/sources.py::skill_snapshot()` | 复用加载入口，保留原契约2与固定重试 |
| 用例生成 | `backend/app/modules/case_generation/sources.py::skill()` | 复用加载入口，保留契约3及旧契约2历史读取 |
| 用例分析 | `backend/app/modules/case_analysis/service.py` 的准备流程 | 复用加载入口，保留契约1及已有快照 |

现状依据是源码，未检查真实数据库任务或在线服务，不宣称历史任务均已有完整 Skill 快照。

建议增加实际需要的 `modules/skills/router.py / schemas.py / service.py`，提供固定注册清单、安全文件清单与读取、管理员修订保存和公开快照函数。文件清单为每项登记相对路径、显示类型、用途、是否参与当前调用和可否编辑。各分析模块单向调用快照函数；Skill 模块不反向依赖分析服务，输出校验仍归各分析模块。只读参考文件直接来自功能目录，无需复制到修订表；任务仅固定实际调用文件，不因展示更多文件扩大AI输入。

页面 GET 和分析准备读取同一个有效内容标识，完整冻结正文、契约、版本、修订和哈希。Worker 不重新读取最新文件或在线修订。现有任务 JSON 元数据可容纳新增快照信息时优先复用，不为每个模块另建 Skill 关系表。

缺少旧指令的历史任务明确提示「未保存当时的 Skill 内容」，不将当前文件冒充历史快照。若因此不能保证固定输入重试，则拦截该重试并引导明确新建分析；不自动修补历史或收费重跑。

本期候选接口四项，文件接口仅承载只读预览：

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/skills` | 有效登录用户 | 五类固定清单、版本/修订及读取状态 |
| `GET /api/skills/{skill_key}` | 有效登录用户 | 文件树及用途/调用/编辑标记、版本和当前内容标识 |
| `GET /api/skills/{skill_key}/files/{file_id}` | 有效登录用户 | 所选登记文件的完整内容、展示类型和哈希；SKILL.md返回有效修订 |
| `PUT /api/skills/{skill_key}/content` | 平台管理员 | 提交正文及预期内容标识，追加有效修订 |

固定 Skill 白名单及服务端登记的文件ID映射到根目录内文件；不直接接收任意读取路径、URL或脚本参数。解析实际路径后复核所属功能目录，拒绝路径穿越及符号链接越界；文件删除或清单过期返回404并允许重新加载清单。未知项404、内容读取失败明确报错、降权403、并发或底版变化409、正文不合法422。加载失败不能显示空白并允许保存。

前端接入 `Skills` 业务组件与 `skillApi`，复用 `api/http.ts` 和主题控件。接口不返回 AI/GitHub 密钥、任务资料或系统绝对目录；日志不输出完整指令正文。

## 8. 验收与推进顺序

关键验收：

1. 五项顺序、名称和文件树准确，Markdown/JSON/脚本/历史约定分别正确展示；无缺失文件补造、目录混淆或内容合并。页面标明实际调用文件，其有效内容与新任务快照逐字一致。
2. 普通用户无编辑入口，直接构造修改请求仍403；项目负责人无额外权限；管理员中途降权保存失败。
3. 管理员修改、预览、取消、保存、重复提交、冲突和失败保留草稿均符合上述规则。
4. 更新只改变新准备任务；已准备/排队/运行、固定重试和历史成果保持原文及哈希。
5. 底版/契约变化明确拦截，不静默混用；历史缺快照不补造。
6. Markdown 长文、表格、代码块和恶意 HTML 安全显示；JSON原文保留、脚本不执行、相对链接只定位登记文件、路径穿越及符号链接越界拒绝。1440px、390px及文件树键盘/焦点对照原型验证。
7. 后续开发运行前端请求/UI回归、类型/格式/构建、后端权限/并发/快照测试与架构检查；若落表，还需中文数据库注释及 Alembic 一致性、真实迁移检查。

建议顺序：审阅本方案 → 同步总原型 → 按确认原型接入页面、修订及五类任务快照 → 验证权限、历史边界与视觉。原型及正式开发按后续指令推进；本轮仅检查设计文档的路径、引用、现状和边界，不运行或宣称业务验收。

## 9. AI辅助修改

管理员在正文编辑弹窗点击「AI辅助修改」，桌面展开右侧对话区，左侧保留正文编辑/预览。窄屏上下排列；文件树的图标、文件名和说明靠左，仅子目录保留层级缩进。

流程：输入修改要求 → 核对发送范围 → 使用本人AI进行对话 → 查看修改前后对照 → 人工应用到草稿 → 管理员另行确认保存。AI不能直接修改有效Skill、契约、脚本、模块绑定或平台权限。

默认上下文为本次完整正文草稿及只读 `contract.md`；可勾选当前Skill内的参考文件。每轮固定实际正文、契约、参考文件、修订及对话，不自动加入全项目资料或其他Skill聊天；修改要求是本轮关注点，不能突破平台固定权限与必要结构。正式调用仅使用该管理员本人的AI配置，不回退其他人或平台配置。

对话按真实管理员账号和Skill隔离保存，支持连续追问。响应保存为建议正文，显示实际变化部分及完整修改前后正文；管理员可放弃建议或应用。应用前复核管理员身份、当前修订和生成建议时的草稿，发生任何变化均不覆盖，保留现有内容供重新讨论。已应用建议防重复；应用后仍未保存，不触发收费重跑或修改历史任务。

发送中显示等待并防重复，可取消；失败、取消或权限变化后保留对话与草稿，重试由管理员主动发起。实际取消前端等待不等于模型已停止；正式接入时按现有后台对话规则记录真实状态，不把取消视为免费或自动重试。
