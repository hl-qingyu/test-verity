## 一、真实目标与工作主线

平台主要供测试人员使用。用户的实际工作是：拿到需求文档和原型，对每个功能检查有没有遗漏、不合理、不完善的地方，把有依据的风险带给产品沟通，记录产品确认怎么改，再对照修改结果复核。

主线为：选择需求与原型 → 首次分析校验后功能风险清单入库 → 关联专属需求分析对话 → 查看风险与依据 → 人工记录产品确认和修改要求。后续对话与追问只保存消息，不修改系统业务内容；只有用户明确发起“添加为风险点”并补全信息、确认入库时才新增风险。不要求每条风险都有对话。

一个功能可以跨多个需求章节、原型页面和公共规则。原型页面树是资料选择结构，不直接等同于业务功能清单。已检查未发现问题、尚未检查、依据不足必须区分；AI判断和格式校验不能当作测试通过。

## 二、分析记录与对话关系

清单展示（最新确认）：需求分析页下方累计展示项目内多次已完成分析产生的功能和风险，不默认只展示某一次分析。上方为紧凑的累计统计与可展开分析记录，不使用某次分析标题或结论代表全部结果。按来源分析筛选只是清单过滤，可返回全部；未完成分析显示状态，不算零风险。各条风险保留来源分析，按“来源分析ID＋风险ID”定位处理及追问；同名功能/风险不自动合并或覆盖。导出可跨分析选择功能与状态，并携带来源信息。

页面分工：保留独立对话页。需求分析页维护功能风险清单、依据、人工处理并提供“导出风险清单”；不设独立报告或快照操作。对话页左侧统一切换需求分析对话、各功能独立对话及历史会话，中间聊天，右侧只展示关联资料和风险引用。风险追问进入所属功能对话，引用可返回风险详情。

一条需求分析记录统一关联以下内容：

1. **资料与范围**：所选需求固定版本、原型HTML/图片文件、链接页面或GitHub文件，以及本次附件等实际采用的依据；不设必选主需求。
2. **功能风险清单**：已分析功能、风险、依据、影响、完善建议和需要产品确认的问题。
3. **人工处理**：产品确认结论、修改要求、处理历史、复核情况；确认怎么改不等于已经解决。
4. **分析对话**：一个需求分析对话，以及按功能分别保存的独立对话。
5. **风险清单导出**：选择一个或多个功能和处理状态，组合筛选导出；默认全部，显示实际条数，无匹配不生成空文件。导出包含依据、影响、建议、人工确认和新增风险的会话来源。

需求分析对话检查整体需求、功能遗漏、跨功能规则和总体审查情况。各功能对话围绕对应功能展开，分别保存聊天历史和上下文；切换功能时恢复其原有讨论，不把其他功能的聊天自动混入。风险上的“追问”进入所属功能对话并附上风险引用，不为每条风险另建会话。

需求分析对话和功能对话共享有来源的审查结果及最新产品确认，聊天不能修改功能、风险、依据、处理状态或原始分析结果。AI回复旁的“添加为风险点”仅打开人工编辑窗口：可选中回复片段作为问题线索，确认所属功能、标题、等级、描述、原文来源/位置/摘录、影响和建议后入库为待确认；保存会话/消息引用、操作人和时间。取消不入库，重复提交同次操作不重复新增。聊天引用不能冒充需求或原型原文。新增项独立保存，原始AI输入和结果保持可追溯；人工处理在清单中明确操作。

对话使用自然语言；首次分析结果才应用结构化契约，不能要求每轮聊天生成JSON或新版报告。历史导入结果可作为讨论起点，原输入、结果和处理历史保留，不虚构导入前的聊天。

## 三、五类分析职责（保留已确认方向）

| 类型 | 目标与输出 |
| --- | --- |
| 需求分析 | 对已确定需求检查风险、遗漏、歧义、一致性及可验收性；按功能集中展示问题、依据、影响、完善建议和待确认事项，不擅自重新设计需求 |
| 用例生成 | 首次依据完整已选需求生成整套用例；需求更新后提出新增、修改、停用或保持不变；保留人工修改及设计/执行历史 |
| 用例分析 | 审查现有用例是否符合需求、缺少场景、步骤/前置/数据/预期不完善；区分需求不清与用例错误，不以覆盖率为主 |
| 代码分析 | 检查Bug、需求偏差和前后端一致性；全部授权业务代码或所选仓库/目录/文件均可；跟踪页面→请求→后端→数据→返回→展示的证据链 |
| 变更分析 | 需求变化影响代码/用例；代码变化影响功能/风险/回归范围。复用代码检查结构，区分本次引入、原有问题及无法归因 |

五类职责不强制串成固定流水线。代码静态分析不代表运行验证通过；缺少关键依据时提示补充，不擅自扩大读取范围，不把本次没再发现问题当作旧问题已解决。产品原文、已确认澄清、测试人员假设和AI建议分别标识。

## 四、资料选择与版本

- 创建分析记录时，需求和原型至少选择任意一项，各种来源均非单独必填，不设主资料或主需求。原型包含HTML文件、图片文件、原型链接、GitHub四种方式；HTML和图片直接列出已有文件及固定版本供勾选，链接保留页面树，GitHub保留文件清单。后续补充复用同一选择方式，不能因只选原型而自动关联需求。
- 需求功能可能仅存在于正文、章节或历史报告里。历史功能与风险是定位线索，必须回到对应版本原文，不将报告内编号自动当作跨版本稳定功能编号。
- 原型链接按目标产品交互展示“读取页面 → 页面树选择 → 预览”。一个最小选择项包含菜单路径、页面内容和该版本已确认批注；批注属于产品规则，随页面加入。父级只负责分组和批量选择。
- 原型页面和批注分别保留引用位置。页面与批注冲突、需求与原型规则冲突均明确列为问题，不静默覆盖任何一方。
- 页面拆分由系统依据可验证结构完成，不让AI猜页面边界。无法可靠拆分的HTML保留整文件选择；视觉识别只能给出有依据的功能候选。
- GitHub HTML按固定提交展示当前授权来源范围内的全部支持文件供选择，支持搜索、全选、清空和逐项选择。记录仓库、提交和文件路径，所需依赖只在授权只读范围内读取。
- 会话文件仅从对话输入区的一个“添加文件”入口加入，不自动进入项目资料库或被其他分析记录引用。保留规则、风险证据引用及移除后的可追溯行为需在正式实现前明确。
- 资料或范围调整只影响后续对话，每轮消息保存当时实际范围。需求或原型更新不能静默替换首次分析依据，原始输入和结果不因聊天改变。

正式系统当前原型链接主要保存URL，实际页面树和批注采集尚未接入。HTML展示最终已确认的产品交互，用明确标识的合成数据演示读取中、成功、失败重试及预览，不把“尚未开发”设计成产品的禁用状态。

## 五、API调用与平台上下文管理（尚未正式实现）

连接方式为：Web页面 → 平台后端 → 当前操作者个人AI服务API。用户通过现有个人AI服务配置使用模型，不依赖某台电脑在线，不使用平台统一密钥或其他成员的配置。

- 平台分别保存需求分析对话和功能对话的消息、范围引用、调用状态及结果关联，持久化平台自己的记录ID。供应商返回的会话/响应ID可以作为执行信息，不能作为唯一历史，也不能代替权限校验。
- 需求分析对话按目标携带整体功能风险清单、相关原文和最新产品确认；功能对话携带该功能依据、必要公共规则、相关风险和本功能历史。需要更多依据时由用户补充范围，不能仅凭摘要宣称完成整体检查。
- 平台负责长上下文整理、必要历史的选取及有来源的摘要。完整可见历史应可恢复；摘要不是已确认业务事实，也不意味着模型无限记住所有内容。
- 每次发起和重试都使用该次操作者本人有效配置，并重新核对项目与资料权限。团队查看审查结果不等于可借用原发起人的AI凭据。
- 接入其他AI按实际API和模型能力处理流式回复、图片、附件、停止等功能，不假定协议相同。切换服务时以平台持有的授权材料和历史组织新调用，不承诺迁移供应商内部上下文。
- 密钥只由后端加密管理，前端不保存或显示密钥。调用记录不写入文档原文、完整提示词或凭据；上传资料和仓库内容始终是不可信输入，不能扩大权限或作为执行命令。
- 不新增通用Agent框架、任意脚本执行器或供应商空实现。正式开发时复用现有公共请求、个人配置和外部客户端分层，只补具体已确认的会话能力。

平台保存历史意味着换浏览器或电脑后可读取有权限的对话，不需要恢复用户本地CLI目录。此处描述目标行为，当前HTML的浏览器演示存储不等于已实现服务器持久化。

## 六、持续执行、停止与失败

- 目标交互支持离开页面后继续、重新打开查看最新状态；正式可靠后台执行仍须按已确认任务和幂等规则实现，不用API进程内临时任务冒充可靠队列。
- 浏览器断线只影响展示连接，不应把它自动当作模型调用取消。平台应保存已接收消息及调用状态，重连后恢复显示。
- 停止操作区分平台已停止接收、已向上游请求停止和上游确认结束，不能将前端取消等待等同于费用立即停止。
- 失败保留已保存历史和明确错误，由用户发起重试，不自动重试可能付费或已经完成的请求。使用重试者本人AI配置，不回退平台密钥。
- 服务超时、长度限制、模型图片能力和中转兼容性仍需真实验证。平台管理上下文不会消除上游限制。

## 七、清单导出、处理记录与现有能力

正式已实现的需求风险v3导入继续保留：input.json与report.json/risk-report.json配对导入，原件关联已有需求/原型固定版本，不重复上传图片/PDF，不恢复attachments目录、旧验收点入口或v2兼容调用。

不新增报告管理模块。清单导出是当前选择功能和处理状态的可携带文件，原型沿用Markdown格式；不新增或覆盖报告快照。历史存量快照和原始AI输入/结果不删除，人工补充风险和处理审计独立记录。

正式API接入后，平台固定首次分析输入，结果校验后入库；后续聊天不自动变更业务内容。模型不能编造输入，不能把聊天中的“已解决”写成处理状态，也不能将分析结果写成测试通过。

ANALYSIS_INPUT_OUTPUT_DESIGN.md继续作为结构化结果与导入导出参考，不是每轮自然对话都要提交两份文件。平台不默认建设由AI提炼事实驱动所有模块的共用知识库；相关性和摘要始终回链原始证据。
