## 当前功能

- 左侧功能模块/功能点树：新增空模块和空功能点、改名、跨模块移动、同级排序、搜索、展开/收起。名称1–80字，同级唯一；同名不自动合并。稳定分类ID，移动功能点会带动所属验收点，空分类保留。
- 节点单行，名称筛选、箭头展开、⋯菜单操作；菜单及选择器使用顶层popover，避免被滚动容器裁剪。方向键/Home/End、Enter、Escape可操作下拉框；移动也可用表单及上下移按钮。
- 验收点支持人工新建、编辑、待补充/待审核/已确认筛选与审核、功能归属调整、来源对照和版本历史。编号项目内递增，新建UUID避免重复提交产生多条记录；重复请求明确提示刷新核对。
- 待补充必须填写问题；待审核或已确认存在问题时必须填写处理结论。形式校验不代表业务语义正确，人工仍需核对内容。修改已确认内容必须先转待审核或待补充，不能直接覆盖已确认版本；未改内容的重复保存不增加版本。
- 业务修改/审核追加不可变版本快照。分类新增/改名/移动/排序/验收点归属变更记录单独审计，不改业务版本与审核状态。撤销仅恢复分类字段，不覆盖之后的业务内容；如果分类已变化或新增分类已被引用则阻断。页面仅保留最近一次分类操作的撤销入口，分类记录查看最近50次。
- 验收点可关联最多50份同项目资料的具体历史版本，用途为需求文档/原型图；手工填写位置与摘录，可移除当前关联（确认后处理，旧版本仍保留）。资料上传新版不自动替换引用。只读预览复用已有图片放大、PDF、Word、Excel及安全Markdown能力，不修改来源链接关联、不访问原链接地址。
- 分析范围/最近需求分析保留顶部折叠区域。AI分析、Skill、建议分类、任务及自动提取均标待接入，无模拟结果、示例业务数据、外部调用、队列或任务表。
- 沿用项目权限：管理员、项目负责人、项目成员可访问并维护本项目数据；不新增角色配置，非成员不可读取或修改。每次写入有Origin校验，过期页面通过项目级revision返回409。

## 实现与数据

`Requirements / RequirementEditor → requirementApi → api/http → requirements/router → requirements/service → documents公开访问校验 + db/models`。

前端仅在frontend；服务不依赖HTTP，路由不写SQL；自定义下拉/操作菜单在FormSelect复用，弹窗复用CaseDialog，原文预览复用Documents的OriginalPreview（新增只读模式）。没有新依赖。

迁移`20260914_11`已落库，六张表及字段均有中文COMMENT：

| 表 | 用途 |
| --- | --- |
| requirement_library | 并发修订号、项目内编号 |
| requirement_category | 两级分类、同级顺序、空分类 |
| requirement_rule | 当前业务字段、审核状态、稳定归属 |

## 接口

前缀 `/api/projects/{project_id}/requirements`：

| 方法 / 路径 | 功能 |
| --- | --- |
| GET 空路径 | 当前分类、验收点、revision |
| POST /categories | 新建分类 |
| PATCH /categories/{id} | 改名/移动所属模块 |
| POST /move | 功能点移动及放到指定功能点之前 |
| POST /assign | 单条验收点归属调整 |
| POST /undo/{event_id} | 校验当前状态后撤销分类操作 |
| GET /classification-history | 最近50条分类操作记录 |
| POST /rules | 人工新建验收点 |
| GET /rules/{id} | 详情及业务版本历史 |
| PATCH /rules/{id} | 保存业务内容和审核状态 |

写请求统一携带revision，服务按既有项目行锁顺序串行校验。不开放删除验收点接口；分类删除规则见最新补充。撤销新增只允许尚未被引用的空分类。

## 功能分类删除（2026-09-14）

模块菜单支持删除，功能点增加垃圾桶图标；应用内确认弹窗显示迁移要求。空分类直接确认；模块有关联功能点/直属验收点时必须选择其他模块，功能点有验收点时必须选择其他功能点。迁移模块下功能点时保持ID、名称与验收点关联，追加到目标顺序末尾；同名冲突拒绝整次操作。功能点迁移保留验收点业务版本与审核状态。无目标提示先创建；取消不提交。

POST `/api/projects/{project_id}/requirements/categories/{category_id}/delete`：confirmed=true、revision、target_id（空分类可空）。项目权限、Origin、同项目目标、类型/自身/重名和revision后端强制检查，迁移+删除+审计同事务提交，不会部分迁移。分类记录物理删除、操作前分类名称保留审计，历史业务快照不覆盖。不提供删除撤销，页面清空上次撤销入口。无表结构变化。测试覆盖空删除、迁移、历史状态保留、跨项目拒绝、未确认拒绝、错误目标、并发和冲突。

## 删除分类的关联内容处理（2026-09-14，覆盖上节非空必须迁移规则）

确认弹窗支持三种mode，默认UNCLASSIFIED（待归类）：

- MOVE：迁移到其他同类型分类。模块的子功能点移动到目标模块，同名冲突拒绝；验收点直接关联被删分类时移到目标分类。
- UNCLASSIFIED：删除当前分类和其下功能点，范围内全部验收点category_id置空，版本/状态/内容保留。模块本身和功能点不会残留在分类树中。
- DELETE：删除当前分类及子功能点，同范围全部验收点记录deleted_at并清空分类；列表隐藏，后续详情/编辑/归类接口拒绝。保留业务版本、来源关联、原文文件和审计，无自动恢复入口。

三种都必须confirmed=true及最新revision，MOVE有内容时必须有效target_id，其他mode不接受target_id。迁移和删除同事务。分类审计保留delete_mode、被删分类名称及验收点删除时间。撤销此前归类也不能让逻辑删除验收点重新出现。

迁移20260914_20新增可空deleted_at时间字段及中文数据库注释，既有验收点不变；存在逻辑删除记录则拒绝降级丢弃标记。真实库注释与模型一致；测试覆盖子功能点内与模块直属验收点、三种处理/冲突/并发、逻辑删除后写入拒绝及业务版本历史保留。
