## 页面

沿用最新原型：项目名称/标识/说明、四张统计卡、五类分析入口、左右等宽的近期分析与关注摘要。用户反馈近期分析过长后，改用紧凑记录行：左侧模块图标，中间模块/编号、最多两行标题和一行时间人员，右侧执行状态及查看入口；部分完成、依据不足、完整性待查看及入库失败标签保留，去掉重复完成标签和每条通用说明段落。完整标题仍在DOM及查看入口可访问名称中，详情可阅读全文。列表桌面最高520px、窄屏最高420px，超出内部滚动，保留全部最多8条；滚动区可键盘聚焦，切页签回到列表顶部。全部、执行中、已完成、失败四页签保持。非零关注项红字/浅红底/红边，零项灰色；窄屏四卡两列、换行入口和上下两个面板。

正式页面没有虚构示例或原型状态切换。首次读取、空项目、筛选无匹配、请求失败、部分模块不可用分别展示。已读取的数据刷新失败可保留并明确标注；账号失效或项目无权访问时清除旧摘要及记录选择。切换项目按账号/项目重建页面，旧请求取消且迟到结果不回填。

首次进入、切换筛选、人工刷新、重新获得焦点及恢复可见时读取；页面可见且存在排队/执行中主分析时每10秒刷新。无活动分析不持续发请求，其他成员新建任务可在重新获得焦点/手动刷新后发现。更新时间是本次汇总窗口，不是跨查询的原子质量快照。

## 计数口径

| 内容 | 来源及口径 |
| --- | --- |
| 需求/原型资料 | 本项目 `source_document`、未逻辑删除，分别按 `REQUIREMENT/PROTOTYPE` 来源数量计；版本及仓库页面不重复累加 |
| 活动用例 | 本项目 `managed_case`、未逻辑删除、`lifecycle=ACTIVE`；不累计设计/测试历史或生成候选 |
| 执行中 | 五类主分析记录的 `QUEUED/RUNNING`，分别显示排队与分析中；不累计批次、聊天和应用条目。任一模块摘要失败则该总数暂不可用，不报部分零 |
| 需求关注 | 报告风险及独立人工风险的 `PENDING/NEEDS_INFO`；按报告条目计，不叠加证据警示 |
| 生成关注 | 分别统计有未应用/未复用/未忽略建议、有未形成确认结论业务问题的记录数量；支持旧固定批次和人工候选。分项可重叠，不相加 |
| 用例分析关注 | 报告问题、说明及人工事项的待确认/已确认待处理；草案已应用不自动关闭问题 |
| 代码关注 | 发现的待处理/已确认/需补充证据分列，排除已处理与误报 |
| 变更关注 | 功能/代码/用例影响、风险及历史复核按未关闭状态计，纯变化说明不计；回归建议的待审阅/暂缓独立计 |

各模块历史未关闭事项按原记录累计，不凭同名去重，也不自动关闭旧问题；不合成一个项目缺陷总数。记录完成、结果完整性、人工处理、用例审核及测试通过互不替代。

近期先按筛选条件查询结果集合，再按创建时间倒序取8条；同时间按固定模块顺序/记录身份稳定排序，不以更新时间让旧记录反复置顶。「已完成」包括执行结束但结果部分完成的记录，仍明确部分完成。历史失败和已取消保留；后续重试成功不改旧记录。

需求任务与其绑定报告只列一条，独立导入报告显示导入结果。代码/变更/生成/用例分析的导入来源取既有快照标记，不猜测。代码/需求/变更和用例分析的完整性来自已保存结果及实际固定ID核对；生成摘要在能确认部分结果时显示部分完成，其余不跳过原模块冲突核对来证明完整，显示「完整性待查看」。

## 记录与关注跳转

「查看记录」进入原模块并读取指定身份。关注分项仅有一条记录时直接进入，多条时使用主题只读选择弹窗，每页20条、上一页/下一页及页码跳转，条目进入原模块并带入对应页签/状态。概览不执行取消、重试、对话、审核、入库或导出。

模块URL携带 `overview=1`、当前 `project`、`record`、`record_type`，关注入口另带 `group/state`。允许的类型：需求为task/report，生成/用例分析为run，代码/变更为task。ID必须为正安全整数；项目、类型和分项状态白名单不符直接拦截，不自动切项目或展示另一条记录。服务器每次详情读取重新执行原模块项目权限。

App的 `OverviewEntry` 负责入口校验及来源提示，提供清除概览筛选、进入模块全部记录和返回概览。刷新/前进后退保留URL中的原定位；模块内其他选择仍按各模块既有交互进行。目标不存在或读取失败显示原模块错误，不退回最新列表第一条。

生成额外使用指定run的轻量摘要读取，避免目标不在第一页时丢失或被其他记录替换。用例分析、代码和变更会直接读取指定详情；需求报告限定累计清单来源，未形成报告的需求任务展开并定位对应任务记录。关注过滤只读，成功应用防重放、版本检查和人工审核规则保持。

## 接口与实现

| 接口 | 作用 |
| --- | --- |
| `GET /api/projects/{project_id}/overview?filter=all\|running\|completed\|failed` | 项目元数据、四卡计数、五模块关注摘要及最多8条近期记录；不可用模块单独列明 |
| `GET /api/projects/{project_id}/overview/attention?module=...&group=...&state=...&page=1` | 固定分项的记录选择，每页20条；返回真实总记录数，不是事项总数 |
| `GET /api/projects/{project_id}/case-generation?summary=true&run_id=...` | 复用生成摘要投影，仅读取指定本项目run；缺失/越权拒绝 |

使用既有有效账号和项目权限，项目内共享，不按创建者过滤；没有读取其他人的AI/GitHub配置。无新增POST/写端点、业务表、迁移、依赖、Worker或统一任务框架。

当前项目概览GET仅保留基础计数和五模块近期／关注摘要，不返回采纳率汇总。AI结果指标改由管理员独立页面读取analysis-acceptance汇总GET，统计口径保持。

后端 `modules/overview` 按router/schemas/service分层，通过各分析模块的公开 `overview.project_summary` 读取摘要；公共标量查询工具位于 `projects/analysis_summary.py`。资料/用例用项目条件在数据库计数。JSONB只投影引用key、当前人工状态、完成声明、已检查/固定用例ID和成功/失败映射所需字段，不读取完整资料、源码、附件、设计正文或尝试历史。前端不遍历所有分页下载全文求和。

关注总量会在服务端遍历本项目的身份/状态投影，输出记录列表有界；不截断总量或存储统计缓存。单模块读取使用保存点，读取/结构异常显示该模块暂不可用，权限错误仍整页拒绝；不把上游错误正文/SQL/资料输出到页面或日志。项目规模增大时仍需关注JSONB扫描成本，本次没有引入持久计数或缓存。

前端 `ProjectOverview/overviewApi/OverviewEntry` 独立于App装配；复用公共HTTP、CaseDialog和PageJump。响应校验项目/筛选/身份/状态/非负计数/可用性，取消与401由公共请求保留；URL中的身份和状态不是访问授权。
