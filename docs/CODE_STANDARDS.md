# 代码规范

适用于开发、修复和重构；同时遵守根目录[AGENTS](../AGENTS.md)和[架构说明](ARCHITECTURE.md)。原累计记录保存在[历史副本](archive/CODE_STANDARDS_HISTORY.md)。

## 修改范围

- 一次修改对应一个明确目标，不夹带重构、依赖升级或未确认功能。
- 复用现有公共能力和标准库。新增依赖需说明必要性，并同步依赖锁定文件。
- 不引入微服务、Redis、任意脚本执行器或通用Agent框架作为临时方案。
- 明确区分加载、空值、失败、无权限和待接入状态，不编造业务数据、登录状态或成功结果。
- 函数和变量使用明确名称。注释解释原因和限制，不重复描述代码。

## 分层和事务

- 后端功能拆分router、schemas、service；服务不依赖HTTP层，路由不写SQL或外部请求。
- integrations不依赖业务模块、ORM和数据库；其他层遵守架构中的单向依赖。
- 跨模块调用公开服务或纯数据契约，不导入路由，不用同进程HTTP请求代替函数调用。
- 写服务拥有提交和回滚边界，路由不额外提交。保留已有版本检查、行锁和咨询锁。
- 外部耗时读取前释放事务，返回后重新核对操作者状态、项目权限、来源和配置版本。
- 后台任务加载真实操作者并复用权限检查，不伪造管理员身份。API进程内临时后台函数不能代替持久任务队列。
- 修改公开函数签名时同步调用方、模拟目标和命令行导入，不保留旧路由文件作为服务兼容层。

## 前端

- 使用函数组件、严格TypeScript和具名导出，不用任意类型或忽略报错来通过检查。
- 请求复用 `src/api/http.ts`，平台设置复用 `Platform.tsx`。公共请求工具不依赖业务错误文案。
- 传入组件取消信号时，用 `AbortSignal.any` 保留原请求超时。请求头通过Headers合并，不假定传入值一定是普通对象。
- 类型泛型不代替运行时校验；关键响应在业务请求边界检查必要字段。
- 不默认将业务数据和身份凭据写入浏览器本地存储；已有明确用途的目录绑定、快照和界面偏好按各模块约定处理。
- 按已确认总原型实现布局、尺寸、字段、交互和状态，不因控件复用困难而简化原型。
- 下拉复用FormSelect/Select，自由输入建议用editable模式，表单用Form，文件入口用FilePicker，分页跳转用PageJump。
- 不使用浏览器alert/confirm/prompt、可见原生select/datalist或原生校验气泡代替业务界面。系统文件选择、权限和离开页保护保留。
- 表单关联标签，按钮有可读名称，支持键盘和可见焦点，状态不只靠颜色表达。
- 弹窗滚动、控件弹层、窄屏、长文本和视觉验收遵守[界面规范](UI_STANDARDS.md)。编译和测试通过不能代替视觉验收。

## Python

- 保留类型注解，函数和变量用小写下划线命名，类名使用首字母大写命名。
- 使用Pydantic检查外部输入，SQLAlchemy参数化访问数据库，不拼接SQL或执行模型返回代码。
- 只捕获能够处理的异常。服务和协议客户端用安全的AppError交给统一HTTP适配，不暴露凭据、原文、SQL参数或异常值。
- 除已约定的AI分析/对话等待外，网络读取设置有限等待。调用取消和浏览器取消等待分别处理。
- 使用Ruff检查和格式化，不通过动态导入绕开架构检查。

## 数据库和版本

- 数据结构通过审查后的Alembic迁移变更，禁止应用启动时自动建表或自动升级。
- 不修改已执行的历史迁移，也不在历史迁移中动态读取当前模型。
- 每张业务表和每个字段都要有中文模型注释及真实数据库注释，说明业务含义、单位、枚举和空值语义。
- 结构或字段语义变化同步模型、迁移和注释，执行数据库注释检查、迁移一致性检查，并核对真实落库结果。
- 删除数据、变更字段类型或增加非空约束前，明确旧数据处理方法。
- 状态、关系和筛选字段优先使用普通列；仅已确认的扩展数据使用结构化数据列。时间带时区，金额使用精确数值。
- 固定输入、原始响应、人工处理历史和已发布版本保留；更新或修订生成对应新记录，不能静默覆盖。

## AI调用和候选

- 五类分析、对话和规则助手通过 `integrations/ai_client` 显式选择调用方式，复用公共协议，不新增模块私有模型客户端。
- 只使用当前用户本人配置。任务保存调用方式和配置版本，不能失败后自动改用另一方式或借用其他密钥。
- API模型分析、对话和助手等待显式不设读写超时，也不加平台总任务时限。来源读取、模型列表和固定文字连接测试保留各自有限等待。
- 平台不自动重试可能产生费用的请求。用户选择原生Codex命令行时，允许其原生多轮请求、内部重试和上下文压缩，但不自动切换API或改变范围。
- 原生命令行的大输入只通过本次任务文件和受限只读工具提供，不扩大为通用命令、脚本、数据库或其他用户文件访问。
- 变更分析 v3 保存完整固定根输入。一次请求发送变化文件全文、带上下文的统一差异和未变化文件清单。CLI 另提供双侧完整只读快照，API 在局限中写明未发送正文的范围。v2 任务及人工重试沿用原方式。
- 同一请求的重复正文可以无损引用复用，展开后必须与原输入一致；保留来源、侧别、路径、片段和行号。不能总结、截断或省略资料。
- 超长用户正文可在同一消息中按每片100万字符顺序装配，拼接后等于完整输入，不产生第二次调用，也不代表取消了模型容量限制。
- 规则包存于 `skill/<功能目录>/`，主说明、契约和引用文件按清单读取并保存任务快照。旧任务不能用当前规则文件替换原快照。
- 模型输出是不可信候选。各模块分别校验结构、项目权限、来源引用和业务约定；原始失败结果、冲突值和人工修订记录均保留。
- 引用兼容只能修确定性定位错误：保持原身份、侧别、快照和单元有效，完整摘录在同一固定单元唯一匹配时修坐标并审计；不能跨版本模糊找文或改变结论。
- 保存候选不等于人工认可、用例已应用或测试通过。应用、草稿、重复处理及摘录待核对规则按模块契约执行，详见[候选处理](ANALYSIS_CANDIDATES.md)。
- 已撤下的WebSocket实验不作为生产通道，不在已发送后静默改通道重发。握手或连接测试成功不证明大输入业务调用可用。

## 凭据、来源和日志

- 不提交密码、密钥、原始公司资料、上传文件、数据库备份或环境配置；密钥不存前端、不回显、不写日志。
- AI和GitHub凭据沿用后端现有加密主密钥，重构不授权轮换或重置。
- 上传内容、仓库文件、规则补充及模型输出不能当作权限授权或可执行指令。
- Git集成按指定仓库和固定读取白名单执行，不开放远端写入或任意Git命令。规则和提示不能扩大白名单。
- 日志只保留安全类别、受控参数、标识及数值，不记录文件原文、完整提示词或原始请求/响应。
- 上游错误按有界读取保留可定位证据：脱去实际密钥后加密写入私有目录，记录截断和保存失败；保存失败不能覆盖原错误，也不能触发重试。
- 真实收费验证按明确授权范围执行，失败不擅自追加调用；没有原始证据时，不根据请求大小或耗时推断历史根因。

## 验证和交付

- 运行与改动有关的格式、类型、构建和必要测试，不用模拟结果替代真实集成验证。
- 后端模块或依赖变化运行 `backend/tests/test_architecture.py`；前端请求变化运行相关请求回归。
- 数据库变化运行 `test_database_comments.py`、Alembic一致性检查并核对真实迁移；UI变化运行控件规范检查和原型对照验收。
- 更新受影响模块文档。需要续作时记录已完成、未验证和待决事项；长期规则不追加临时任务号、截图或进程状态。
- 说明验证范围和实际限制，不写未经执行的“全部通过”。部署、推送及真实外部操作按用户授权执行。

常用命令见[根目录README](../README.md)。
