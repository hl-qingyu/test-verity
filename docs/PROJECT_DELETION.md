# 项目逻辑删除

## 现行规则

项目负责人和管理员按修订号确认删除。活动分析、对话或入库申请拦截删除。项目数据逻辑归档，各读取入口重新检查项目状态。

2026-10-16用户确认：平台管理员和项目负责人可以删除项目；采用逻辑删除，保留关联数据；存在排队或执行中任务时禁止删除。

## 页面与接口

项目设置 → 基本信息底部增加“删除项目”。普通成员不显示入口。应用内确认弹窗显示项目名称、数据保留及活动任务限制；提交时禁用重复点击和关闭，失败保留弹窗及原因，成功刷新项目列表，自动选择剩余项目；最后一个项目删除后显示原有未选择项目状态。

`DELETE /api/projects/{project_id}` 接收 `{version, confirmed: true}`。沿用登录、Origin、项目权限；service重新读取并锁定项目行，仅管理员/负责人允许。版本变化返回 `project_changed`；有活动任务返回 `project_delete_active`；不存在、无项目权限或已删除返回404。原项目标识继续占用，避免新项目与历史数据混淆。本期不新增恢复或永久清理入口。

## 事务与数据保留

删除检查五类主分析任务、生成批次、五类记录独立对话及两类审核入库申请共13条路径，状态QUEUED/RUNNING阻止删除。已有入队操作同样通过公共项目访问获取项目行锁，与删除串行；已有任务完成后可重试删除。正在读取外部资料的请求保存前继续使用已有权限复核，删除项目不授予继续读取或入队权限。

迁移38只为project增加`deleted_at`、`deleted_by`，模型和真实数据库均带中文注释，后者关联用户。成功时记录操作者/时间并递增version；关联表、资料文件、用例、报告、审核记录及历史版本保持原件，不删除本地代码或远端仓库。已有删除审计时禁止迁移降级丢失审计。

项目列表和公共`access_project`拒绝已删除项目，普通成员、负责人、管理员均不能通过原项目链接继续访问；所有项目的AI结果验收只读投影排除已删除项目。项目负责人仅拥有已删除项目时，账号选项查询不再把该项目当作管理资格。资料的来源绑定、分析记录的逻辑删除、Skill管理及个人AI配置不变。
