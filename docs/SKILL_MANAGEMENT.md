## 文件与权限

固定五类、顺序沿用工作台：需求分析、用例生成、用例分析、代码分析、变更分析。程序源文件仍在项目根目录 `skill/<功能目录>/`；页面展示实际文件树，本轮37份文本，不包含缓存和跨版本分发包。

有效登录用户可查看；仅有效平台管理员能保存和使用修改对话。项目负责人无额外权限。后端根据固定Skill白名单及文件ID解析文件，拒绝路径穿越、文件符号链接及越界；只允许保存 `SKILL.md` 正文。契约、示例、脚本和开头YAML元信息保持只读，脚本不执行。Markdown复用安全渲染器，相对链接只定位本Skill中已登记文件，外部地址/媒体不自动读取。

文件由后端统一读取，用户浏览器不需要操作系统文件权限。后端运行账号需能读取Skill目录、写入可编辑文件及同目录临时文件、写入私有备份目录。功能不提升Windows权限、不提供任意文件写入接口。

## 保存与实际调用

```text
PUT /api/skills/{key}/content
→ Admin身份依赖 + 请求来源校验
→ skills/service.save：复核当前账号，复用账号变更事务锁防止降权竞态
→ skills/files.write_body：跨进程文件锁、完整文件组内容标识比较
→ 私有旧字节备份及写入意图回执落盘
→ 再核对当前文件，临时文件fsync后同目录原子替换
→ 返回新目录内容标识；响应丢失可用原请求UUID重试
```

备份与回执在 `backend/storage/skill-backups/`，不开放下载接口。回执保存修改人ID、时间、旧新哈希及请求指纹；旧文件保留原字节，保存保留原元信息和换行风格。备份失败不写源文件；相同UUID内容不一致或旧内容标识失效均409。应用内所有读取/保存共用文件锁，避免读到本次写入中间状态。

外部编辑器不参与该文件锁；保存会在备份后再次比较原字节，但不承诺对不遵守锁的外部进程提供文件系统级比较交换。部署维护时应避免同时从其他程序写同一Skill。当前API与单Worker共享同一目录，未新增跨主机文件同步。

五类分析统一从 `skills/files.snapshot` 取得实际运行指令、版本、契约版本和SHA-256并固定到任务。声明resources.json的包按有序清单加载运行Markdown及完整文件快照；无清单保持 `SKILL.md＋contract.md`。未登记的示例/脚本不自动参与调用。当前文件按UTF-8读取，CRLF投影为LF；任务哈希基于实际拼接指令，目录冲突标识及备份仍基于原文件字节。

需求分析改为入队前固定完整Skill，Worker及固定输入重试使用原快照，不读取当前文件；已存在但无历史Skill快照的任务不补造内容，重试明确拦截并提示新建分析。其余四类沿用各自已有准备/重试快照。旧报告、用例、聊天和已保存指令不改写；不会自动重跑。

代码分析原硬编码2.0.0标签已改为实际文件声明2.0.1；用例分析新快照采用统一的指令字节SHA-256，旧快照原哈希不重算。

## AI辅助修改

管理员编辑弹窗沿用原型正文/预览及右侧可展开对话。发送前可核对范围：默认当前完整草稿、参与调用的只读规则与契约，可选择其他本Skill参考文件，可显式取消携带历史对话以缩小上下文。提交使用本人当前有效AI配置；配置元数据入库，不保存或返回密钥。

对话通过现有 `app.chat_worker` 排队执行，按真实管理员账号＋Skill隔离。请求UUID、完整请求指纹、对话末条ID及活跃轮次唯一约束共同防重复；不自动重试可能计费的调用。可取消，取消前端/平台任务不承诺上游免费或已停止。Worker启动仅将中断的RUNNING标失败，不重放。

模型按固定编辑指令返回 `message＋body`，只形成中文说明及完整正文建议。平台严格校验、保留原始响应；未通过不生成可应用建议。输入文件及历史消息是数据，不能授予执行或写文件能力。

完成后自动展示变化部分及完整修改前后正文。管理员应用前重新读取文件内容标识，核对生成时草稿；文件或人工草稿变化均不覆盖。应用只改草稿，仍需另行保存确认。旧建议不可对新文件版本直接重放。

前端按用户ID隔离工作区，切换Skill/文件有取消和身份校验，普通用户无编辑入口。刷新/关闭有系统离开保护，应用内导航使用已有数据路由的阻断和主题确认。失败保留草稿，重复提交即时锁定，响应未知时复用原请求身份核对。

## 读取性能与缓存

原页面首次读取列表、目录及正文三次请求，之后每次文件切换都重新请求、清空预览；单文件接口实际又扫描并读取整个Skill包。当前固定五包合计约284KB原文，采用以下优化：

- `GET /api/skills/{key}?include_contents=true` 一次返回目录及该Skill的完整文件内容。携带 `known_token` 时，内容标识未变只返回目录与 `unchanged=true`，省去正文重复传输；`refresh=true` 强制重新读取，不依赖浏览缓存。原单文件及默认目录接口保留。
- 仅列表、批量浏览及单文件浏览使用 `files.cached_bundle`。每次请求先校验白名单、目录与文件标识（设备/文件身份、大小及纳秒修改时间等）；变化立即重建内容缓存。进程内最多五包、每包最多8MiB缓存，超过则保留原直接读取语义；最长5秒到期重读，避免相同时间戳等特殊变更无限沿用旧内容。到期仅在后续请求时重读，不新增后台轮询任务。
- 浏览缓存返回独立副本，线程锁合并同包并发读取；保存成功立即清除该包缓存。鉴权仍在每个HTTP请求之前执行，缓存命中不绕过登录校验。
- 前端只在当前用户的Skill工作区内存保存已加载的文件包，不写localStorage。点击已读文件直接显示，不逐文件请求，也不先清空预览；切回看过的Skill先展示再后台核对。切换文件距上次校验超过5秒、返回窗口焦点时核对，保留原有重新加载按钮用于强制读取。
- 编辑期间不更新编辑器的基准内容，保存后丢弃该包前端缓存并强制重读；新开编辑、应用建议、保存、AI入队和分析快照继续走未缓存的最新内容/权限校验。旧模块的迟到响应不能覆盖当前模块；离开页面、切换账号或鉴权失效清理缓存。
- 预览内容与显示方式未变时复用Markdown/JSON渲染结果，避免校验状态变化导致整份文档重复解析。后台校验失败明确显示原因并禁用编辑，不把旧缓存当作已核对成功。

本机同进程直接服务函数五次样本（非HTTP/真实账号端到端）：列表原约18–29ms，缓存预热后约9–11ms；单文件原约5–7ms，预热后约3–4ms。前端收益主要来自消除逐文件网络往返和空白等待，不用这些数字承诺用户端固定耗时。
