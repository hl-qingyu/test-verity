# 代码规范

## 通用

- 2026-11-12用户明确允许原生Codex CLI业务调用的多轮请求、CLI内部重试与上下文压缩，并确认超stdin上限时由独立任务目录/受限只读工具读取完整固定资料。此授权仅针对显式选择CODEX_EXEC的任务，替代该方式的旧单次/禁内部重试门槛；原RESPONSES_API不变。平台不偷偷改任务范围、不自动回退API/另起任务，原输入/Skill/引用校验/人工审核及本人凭据边界仍保留。受限工具只读取本次input.json；不扩大到命令、数据库或其他用户文件。详见AI_CODEX_CLI_IMPLEMENTATION.md。


- AI证据定位兼容只可修确定性坐标：变更分析非代码TEXT摘录的片段编号错位，须在原比较对/侧别/快照/单元身份有效且原片段存在的前提下，确认完整原文在同一固定单元仅出现一次，才可改segment_id并审计原/新编号及位置。不得模糊匹配、跨版本/单元找相似正文或改摘录/业务结论，歧义与无效引用仍拒绝；原候选、固定input/Skill保持，修后执行全部契约校验，配对导入仍严格。不能把“已有下载入口”当作校验失败已修复，必须核对实际候选并验证原记录恢复。

- 改变AI传输必须验证实际生成能力，握手/控制帧成功不能当作大输入可用。2026-10-26 WS610实测无可用上游账号，候选已归档撤下，五类仍走原共用HTTP；不得恢复为默认或在已发送后静默换通道重发。真实验证仅限用户明确次数，失败即停；未知中转版本/权限不能靠客户端猜参数绕过。见AI_WEBSOCKET_TRANSPORT.md。

- 上游AI错误必须保留可定位证据，不能只存未知错误码后永久丢弃原因。公开日志/共享任务只放受控类别、参数、UUID/指纹与数值；任意上游正文可能回显公司资料，须先脱实际API Key，再由既有主密钥加密存私有诊断目录，不允许明文日志或新公开下载。捕获有容量边界且明确标截断；失败存储不覆盖原错误、不自动重试收费请求。历史未保留正文不可补造，也不能把合成错误场景当历史400根因。详见AI_SERVICE。

- 2026-10-26用户最新要求变更分析将全部所选固定内容一次交AI。新建/人工重试用FULL_INPUT，不按平台静态图筛减文件/上下文、剔除目标或预排语义复核；关联、影响、配对和归因由AI基于完整根输入判断。平台只负责授权读取/固定事实、本人共用模型通道、取消/安全/完整结果保存与严格引用校验。验收必须证明最终请求重组后等于完整根input及原二进制，不把“根数据仍在库里”当作已交AI。旧分批只作历史审计/兼容，多次独立分析不等价同一上下文；失败不自动截断/缩范围/分批/收费重试。见CHANGE_ANALYSIS_FULL_INPUT.md，此条替代旧分批默认约定。

- 2026-10-26变更分批必须围绕待核查关系提供完整证据，不能按路径/字节切开依赖后只加缺口提示代替工作。共享必要依赖可重复，规则/实现/用例同包；前后端按每个主变化的实际方法/路由候选配对，不取任意首/最小文件凑角色。跨批关系复核必须预列次数且引用本批原件，其他批报告为待核查数据；同根因合并及冲突处理必须保存原证据、原措辞和人工审计。旧V1计划不静默升级执行或误复用旧范围结果，应新记录重新准备并展示次数。静态候选与真实模型效果边界明确，见CHANGE_ANALYSIS_BATCHES.md。

- 2026-10-22变更分析已获授权按文件及静态依赖分批。完整根输入/旧Skill保留；较大计划先保存并展示实际调用次数，只有发起人开始后才调用本人AI。成功批次和人工处理可在新重试记录复用，失败及未开始批次仅人工重试，禁止把相同收费调用静默重发。共享协议仍由responses负责，批次规划和结果合并属于业务模块；汇总必须验证根引用并标明未处理/跨批证据缺口。其他分析不能据此擅自自动分批。状态/权限轮询使用必要列，批次持久化不能反复传输整份固定输入或原选择。见CHANGE_ANALYSIS_BATCHES.md。

- 2026-10-22用户明确：现有及后续AI分析不得由平台设置总时长或socket读写等待上限。五类分析、独立对话及Skill编辑助手统一复用`integrations/ai_client`显式方式分流门面及`integrations/responses`的HTTP模型请求入口、SSE完整结果接收、错误分类与安全诊断；不要新增模块私有超时、HTTP客户端或自动收费重试。业务模块只组装已授权固定输入/Skill、提供权限/取消检查、保存原始候选并校验各自输出。分析等待显式`timeout=None`，不依赖全局socket默认值；来源读取、模型目录和固定文字连接测试保留各自有限网络超时。
- 同一AI请求中的重复长正文可由公共`response_input`作无损引用传输：全部文件、双侧身份、路径、片段、行号和文字均保留，展开与原输入等价；只复用完全相同的文字，不总结/截断/缩范围或改变资料权限。原任务输入、Skill快照、报告和历史不可改写。系统追加传输说明不改变业务规则；无重复的小输入及非JSON正文原样发送。中转/模型返回504、断开或不完整结果仍明确失败，不能称平台取消限制就证明上游问题已解决。
- 超长user正文统一由`response_input`在同一消息内顺序拆成多个`input_text`，当前每片最多100万字符；此数只控制协议字段装配，不限制合计输入、不截断正文，也不产生第二次AI调用。追加说明要求连续片段无分隔拼接后解析，图片/PDF位置保持。小输入/Skill规则与原任务快照保持。日志只留受控错误类别/码/参数、错误指纹、请求/片段尺寸等安全诊断；不得把超长单字段、总上下文超限、超时和通用400混为同一原因，也不得凭离线检查宣布真实模型调用已修复。

- 一次变更对应一个已确认目标；不夹带重构或无关升级。
- 使用明确名称和小函数，注释解释原因与边界，避免复述代码。
- 边界输入必须校验；禁止硬编码凭据、拼接 SQL、执行模型返回的代码。
- 日志不包含密码、Token、文档原文、完整提示词和数据库连接字符串。
- 空数据、加载中、失败、未授权和未实现必须分别表达。
- 依赖新增需说明现有能力为何不足；提交对应依赖锁文件。

## React / TypeScript

- **UI按已确认原型实现，不允许擅自简化。** 覆盖所有现有及后续页面、弹窗和控件，不能以省事、赶进度、先实现功能或复用现有组件为由，改用简单控件、简化布局或省略交互。优先复用符合原型的主题组件；组件能力不足时补齐外观和交互，而非降低原型要求。
- 开发前核对原型的布局、尺寸、间距、按钮、下拉展开项、弹窗及状态；交付前对照核验正常/加载/空数据/失败/禁用/选中状态、长文本、窄屏、键盘/焦点、遮挡和溢出。功能可用、类型/测试/构建通过不等于UI验收通过；未完成视觉验证须如实记录。偏离已确认原型须先说明具体差异并取得用户确认。

- 所有现有及后续可见控件遵守`UI_STANDARDS.md`：下拉及其选项复用`FormSelect`/`Select`，自由输入建议用editable模式；文件入口复用`FilePicker`，表单复用`Form`显示应用内校验提示。禁止原生select/datalist选项界面、window.alert/confirm/prompt和reportValidity浏览器气泡，不用新页面作为例外。
- 代码分析及后续分析页面必须先对照确认总HTML原型实现；复选框、文件树全选/清空、工具栏和弹窗使用现有主题样式或模块共享样式，不能用未主题化的原生可见控件代替原型交互。
- 按钮、业务弹窗及提示必须使用已有主题样式/组件；button、dialog、popover仅作为语义与顶层弹层底座，不等于允许浏览器默认外观。系统文件窗口、权限窗口与刷新/关闭页离开保护由系统控制。运行`tests/ui-controls.test.cjs`防止回退，页面改动仍需相应类型/格式/构建及交互检查。

- 平台设置容器放 `Platform.tsx`；账号、AI、GitHub分别作为功能组件。应用装配入口依赖功能模块，功能模块不反向依赖容器。
- 共享JSON/加密请求使用 `src/api/http.ts`；请求工具不得依赖业务页面或业务错误文案。错误映射归属对应业务API模块。
- 传入组件卸载的AbortSignal时，必须通过 `AbortSignal.any` 同时保留超时。请求头使用Headers合并，不能假定headers一定是普通对象。
- 通用请求的TypeScript泛型不等于运行时响应校验。新增关键接口须在业务API边界校验必要字段，不用类型断言冒充校验。
- 不为历史登录/AI界面做无关批量改写；后续修改其请求逻辑时复用公共能力，不再新增第三套传输实现。

- 使用函数组件、严格 TypeScript、具名导出；禁止 `any` 和忽略类型错误来通过构建。
- 页面组件按已确认功能增长，再提取真正复用的组件；不预建整套目录树。
- 服务端数据通过 `/api` 获取，不直接调用 AI、GitHub 或数据库。
- 表单关联 label；使用原生按钮、键盘可达控件和可见焦点；状态不单靠颜色。
- 默认不使用 localStorage 保存业务数据或身份凭据；登录方案另行确认。
- ESLint 检查，Prettier 格式，`tsc` 类型检查，Vite 构建。

## Python

### 分层与模块（2026-09-12已实施）

- 目录与调用示例以 `ARCHITECTURE.md` 为准。新增已确认功能放 `app/modules/<功能>/`，按需要创建 `router.py`、`schemas.py`、`service.py`。
- `router.py` 仅处理协议：参数/密文解析、身份依赖、Cookie、状态码及调用服务。不得直接执行 SQL 或发出外部网络请求。
- `service.py` 接收Pydantic输入、明确操作者和普通SQLAlchemy Session；负责资源权限、业务校验、事务和结果，不接收FastAPI Request/Response/Depends。
- 服务及外部客户端抛出 `core.errors.AppError`，detail是安全错误码。由main统一映射HTTP；不携带上游响应、Token、SQL参数或堆栈。
- 服务不导入其他模块的router或任何app.api文件。跨模块只调用明确的公开服务/数据契约，形成单向依赖；不通过HTTP调用同进程模块。
- `integrations/` 只处理固定外部协议、超时、响应大小和白名单；不得依赖业务模块、SQLAlchemy或数据库Session。
- `security/` 保留通用密码、密文封装、限流与凭据加密机制；允许加密的HTTP路径由 `api/encryption.py` 维护，不放回加密核心。
- `db/` 管连接生命周期和ORM声明，不承载业务流程；`core/` 不依赖上层。
- 服务直接使用SQLAlchemy，不强制增加仅转发一层的Repository、接口类、工厂或注入容器；复杂查询出现真实复用再提取。
- 修改公开服务签名需同步调用方、mock目标和CLI/Alembic导入；不得保留旧路由文件充当公共服务兼容层。

### 事务与安全语义

- 写服务拥有事务提交/回滚点，路由不得额外提交；保持已有版本检查和行锁/咨询锁。
- 外部耗时请求前释放事务；远端返回后重新核对操作者、授权和版本，再写入。
- 服务调用方必须传入可信且已验证的操作者；未来Worker要加载执行时有效身份并使用同样的资源权限检查，不伪造管理员对象。
- 不自动重试会产生费用或可能已完成的操作。取消前端等待不等于后端或上游已经取消。
- 密码挑战与限流目前进程内保存，仅支持单API进程；扩容前另行确认共享状态和密钥管理，不能直接增加workers。
- GitHub与AI沿用既有 `AI_ENCRYPTION_KEY` 保存的主密钥，以兼容现有密文；不能因重构擅自改Key、轮换或重置凭据。

### 基础规则

- Python 类型注解、snake_case 函数和变量、PascalCase 类；Ruff 格式与静态检查。
- FastAPI 路由负责协议边界，业务规则进入对应模块；不要写成万能服务类。
- Pydantic 校验外部输入。使用 SQLAlchemy 参数化访问，明确事务提交与回滚。
- 只捕获能够处理的异常；响应不暴露堆栈或凭据。外部调用保持明确失败状态；除上述用户明确豁免的AI分析/对话等待外，其他外部调用须设有限超时。
- 分析由独立 Worker 运行。任务与幂等规则确认后再实现，禁止用 API 进程内后台任务冒充可靠队列。

## PostgreSQL

- 每张业务表、每个字段必须有中文数据库注释，包括关联表、版本字段和技术字段。表说明用途，字段说明业务含义、适用的单位/枚举/空值意义；不能只用中文“字段”作为占位。
- SQLAlchemy表使用__table_args__的comment，字段使用mapped_column(..., comment="中文说明")。Alembic建表/加列带comment，已有对象用独立迁移更新COMMENT；不改已执行的历史迁移。
- 新增/修改字段必须同步模型、迁移与注释；交付运行tests/test_database_comments.py和alembic check，并核对真实库注释。迁移内容不从当前模型动态导入，确保历史可重放。

- 数据结构使用 Alembic 迁移，禁止应用启动时自动 create_all 修改业务库。
- 关系、状态、筛选字段使用普通列；只有已确认的扩展数据使用 JSONB。
- 时间采用带时区时间，金额使用精确数值；主键、唯一约束、索引随业务确认设计。
- 任何删除、字段类型转换、非空调整先说明历史数据处理方式。

## 检查与提交

- 后端 `tests/test_architecture.py` 检查层依赖、越层导入和循环；新增模块自动纳入。禁止以动态导入绕过约束。
- 前端 `npm test` 检查共享请求的取消、超时、401和错误码处理，不发送真实外部请求。
- 重构对照OpenAPI和现有端点行为。字段、状态码、权限、加密协议不能以整理架构为由改动。

- 修改逻辑需最小可重复检查，覆盖失败路径和关键边界；不要仅断言实现细节。
- 前端运行 `npm run check`、`npm run build`。
- 后端运行 Ruff 和 unittest；数据库变更还需实际迁移验证。
- 提交说明写清问题、改动、验证和未验证边界；禁止宣称未经执行的测试通过。
