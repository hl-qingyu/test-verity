# API / Codex CLI 实施契约

新建用例生成、用例分析、需求风险及 v3 代码和变更分析支持结构化阅读目录。每项按固定资料、文件或用例保存阅读文件，大段按行优先切分，内嵌图片原字节通过标准 filesystem 提供。恢复时认证校验目录和原件后复用已有版本。

终端恢复还原尺寸：会话DTO提供实际启动行列数，旧历史先按该尺寸解释原始光标控制，再适配当前区域，避免宽度变化产生行首残留字。新执行另在私有sizes.enc.jsonl按原始输出帧位置记录初始尺寸和后续resize，沿原密钥加密；原ANSI日志不改写，回放按位置应用尺寸。旧历史没有记录的中途resize不能补造，本次实际93按原126列恢复的残留行验证已消失。

首次恢复遮罩复用统一generation-spinner旋转图标；已有减少动态效果偏好时遵循主题规则。长日志按不超过约256Ki字符/2048片段的有界页传输，前端在同页内合并连续文本写入，保持原始顺序/内容及cursor语义，避免5万片段逐次细碎绘制。恢复期间不向PTY回传尺寸，ready及历史解析完成后才适配/显示最新画面。


五类分析在各自的历史对话内使用共用原生终端。返回报告时保留画面和连接，重连按 cursor 补新增帧，首次恢复后显示最新画面。缓存保存在当前页面内存，按用户、项目、记录和执行隔离。

## 大文件和内嵌图片的阅读组织（2026-11-17）

原始input.json完整提供，不代表模型已完整看见单次工具输出。此次真实会话中，旧工具一次打印含图片Base64的完整JSON，原生CLI明确提示约580734 token输出被截断；之后“继续”轮未再读取工具，只沿历史输出部分候选。完整输出107149字符、155条候选但complete=false；正常turn完成不等于范围完成，也不是平台30分钟超时。

公共`integrations/cli_reading`在任务目录内从原input.json生成不可变reading-v1-<原件SHA256>阅读目录：按messages原角色、顺序和content序号列出完整正文；正文文件最多4096个Unicode字符，目录按6144字节分页，多层目录同样有界。保留原input.json与其全部业务内容，不概括、不筛选，不创建多个独立业务任务/调用。新增文件只是本次原生任务的阅读表示，全部仍通过原标准MCP filesystem读取，无自定义MCP协议、文件读取工具或任意命令接口。

有效PNG/JPEG/WebP/GIF内嵌data URI按原字节还原为本目录图片，正文只将该URI换成本地文件名；目录记录原message/part、字符位置、URI前缀、字节哈希和替换路径。相同图片只存一份，所有出现位置分别保留。非法或不支持转换的URI（包括现有SVG文本）原样留在正文，不能静默删图。原生`input_image`附件仍走原始原生附件传输；新增内嵌图片沿标准read_media_file和functions.exec的image内容转发进入视觉输入，不能只打印Base64冒充看图。不请求外部图片链接。

新指引要求从目录逐项读取正文和图片，一次输出一个小文件文本；遇truncated必须重新分次读取，不能把被省略的内容当作已读。继续未完成业务时先核对目录、补读缺失资料，再完成设计与反查；可继续完成时不因为内容多或上一轮已有部分候选而提前交卷。原Skill业务待澄清、真实上下文或工具限制仍如实保留，不强制把complete改true，不添加平台自动续发/自动收费重试。

原生TUI首次启动从实际保留的input.json构建阅读表示；后续恢复校验源文件及阅读文件的SHA256，直接复用既有目录，不再解析整包JSON、拆分正文、解码图片或写入临时阅读目录。文件摘要清单沿后端现有主密钥认证加密保存，原子落盘，绑定原件SHA256；篡改文件、伪造清单、缺文件或符号链接明确失败。旧目录首次升级仅完整比对一次并补清单，不改写既有阅读文件。仍另写按内容哈希命名的指令文件，不覆盖旧instructions.txt、固定Skill、原始输入或原生历史；非交互大文件入口复用同一能力，小文本/API通道不变。

恢复同一CLI会话的指引明确要求利用历史中已完整读取且当前仍可用的内容、阅读记录及已有成果，不因打开/恢复会话要求从头重读，也不要求每次重新读目录；仅补读未读、被截断、压缩后缺失或当前问题需要核对的部分。首次分析仍须完整阅读范围，缓存存在不等于模型读过。恢复本身不发送新分析，下一轮由用户输入发起；不伪造持久化的语义阅读完成状态，不保证模型一定不按需复读。关闭弹窗重开只恢复显示连接。

此改进解决已复现的整包文本截断和内嵌图未作为视觉资料提供的问题；不能以目录存在、工具调用或假provider结果证明模型已理解/覆盖全部业务。实际任务仍依原候选/引用/结构校验及人工审核；不自动重跑旧分析或把后续聊天覆盖生成报告。没有新依赖/数据库表/字段/迁移、工具权限或等待时限。


## 受限原生网页终端（现行）

CLI不因平台数据库断连而停止。调度器暂停新任务领取，每5秒尝试连接并重新取得调度锁，已有CLI及预算预留保持；运行中数据库检查失败等待下一次检查，不作为CLI取消。数据库恢复后仍核对真实操作者、权限、配置及任务状态，显式取消/失权继续有效。API调用保留原行为，不因本次修改引入模型自动重试。

调度会话单独使用NullPool和AUTOCOMMIT，每5秒保活；只有该会话设置idle_session_timeout/idle_in_transaction_session_timeout=60秒、statement_timeout=15秒。失联后由PostgreSQL自动结束会话释放咨询锁，不依赖下次人工清锁，也不自动调用pg_terminate_backend。心跳与业务准备/结果交付独立，长任务不触发空闲回收；连接发生错误后不可透明重连后沿用旧锁身份。启动占锁或发现尚活跃的原调用时持续等待，不运行全局恢复、不领取新任务，也不直接退出。两类连接都开启libpq TCP保活以识别失联；SQL执行超时只作用于调度连接，不是CLI或模型任务时限。

每个CLI调用沿原预留UUID在 `AI_CLI_WORK_PATH/results/` 保存独立加密结果：先原子记录启动标记，完成后fsync及原子替换为完整结果或失败信息，再返回业务执行器。业务保存遇到数据库连接异常时只重做固定任务的校验/交付，共用入口读取已有结果，绝不再次启动CLI。交付结束保留原结果并追加delivered标记。Worker重启先检查未交付结果并核对任务/请求/操作者，再执行原校验；旧尝试已取消/变更时不应用。只有启动标记、没有完整结果的未知收费尝试不会自动重发。此能力不使被操作系统强制结束的CLI重新活过来；已完整落盘结果可跨Worker重启交付。

CLI 文件读取直接使用 MCP 项目维护的 `@modelcontextprotocol/server-filesystem@2.3.0`，锁文件在 `backend/mcp/package-lock.json`，需要后端 Node.js 24以上；可用 `AI_CLI_NODE_EXECUTABLE` 指定路径。启动原包 stdio 入口，传 `--read-only --confine-roots <本次input目录>`，由该服务限制目录并只注册读取工具。平台只生成启动配置，不实现文件读取、字节分页、编码解析或自定义MCP协议。原 `codex_files.py` / `verity_input.read_input` / `search_input` 已撤下；没有32KiB的自定义读取上限。标准服务说明见 [上游文档](https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem)。

原生TUI和非交互大输入调用共用上述标准服务。原始 input.json、Skill、消息角色和顺序均保留；文本由标准 read_text_file/read_multiple_files 等读取。模型的上下文与CLI工具输出显示仍由其原生机制处理，不据此宣称全部内容已被模型读完。恢复旧原生会话时保留旧 instructions.txt，生成单独的工具迁移说明文件，明确旧工具已停用并指向 filesystem；不静默覆盖旧固定输入或规则快照。

用例生成的新建和人工重试 CLI 批次经公共 ai_client 进入原生 TUI；入队前在批次 ai_config.generation_terminal 固定私有目录与执行标识，不额外创建终端任务。原 Worker 领取生成批次后自动提交完整固定输入与 Skill，无浏览器也能完成。前端开始成功进入现有历史对话区域内绑定批次的终端，原始 ANSI 与按键仍直接传输；生成取消沿用原取消接口。API 和已在跑的旧 exec 批次不切换。

需求、代码、变更和用例分析新建或人工重试时将私有终端绑定保存到任务 AI 快照。开始后进入当前记录的历史对话，首次有效结果按模块契约进入原报告页。分析结束后可从同一历史显式继续，Worker 使用固定个人配置、原输入阅读目录和明确的原生线程 ID。续接进程通过 `analysis_terminal_resume` 记录，沿原预算、取消及恢复流程运转。控制入口沿用用例生成的本机同源范围。

续聊候选使用本任务私有会话中已持久化的完整助理消息，并用本执行加密 RPC 日志确认对应轮次正常完成。历史对话按轮显示原文，并使用固定输入与对应模块契约计算校验结果。正式报告显示首轮通过校验的结果。历史中的失败或中断轮次保留原生画面。

TerminalResult 只接收本任务首个生成轮的最终完整 agentMessage，正常 turn/completed 后将原文交回原候选保存和契约校验。失败/中断/空文本不当作完整候选；终端画面不参与 JSON 提取。生成完成释放进程，保留 state 与画面，显式继续通过原 chat 队列恢复同一原生历史，后续聊天不自动覆盖报告。显式重试生成使用新目录，原尝试保留旧绑定。主生成和后续聊天的文件执行标识区分命名空间，避免两张表自增编号碰撞；WebSocket 绑定变化时先断开重播，防止重试沿用旧游标。

用户确认处理本机命令越界，保持CLI原生画面和正常对话。原生TUI改为 `--remote` 连接每任务随机令牌保护的loopback代理；真正的app-server仅stdio，无其他可直连监听端口。代理白名单放行只读状态、历史和对话，`thread/shellCommand`、`command/exec`、`process/spawn`、fs操作、插件/配置/MCP写入口及未知方法均不转发。线程创建/恢复/对话固定工作目录及verity只读配置，拒绝权限/路径扩展；服务器发起的权限申请直接拒绝，不允许客户端伪造批准。TUI不持有模型Key，只有app-server获本人Key；代理不可用则失败，不启动无过滤备用TUI。

原始VT与按键传输保持，普通消息标点不屏蔽。固定版本CLI在用户shell请求被拒绝后可能退出，后端以明确的拒绝码保存，用户手动续接历史，不自动再发模型请求。正式报告与用例不因原生对话而自动覆盖。旧临时会话无法恢复。试用账号白名单None沿原项目/记录发起人权限，[]关闭，非空列表进一步限制；不再是“授权完整本机命令”开关。

显示连接与原生任务生命周期分离：返回生成报告不取消原生任务，同一页面保留xterm实例/已解析画面和连接；隐藏时禁止输入及尺寸回传，恢复显示直接到末尾。断线重连以cursor恢复新增帧，服务端仍复查原会话、项目和执行发起人，cursor不能选择其他会话或路径。缓存只在页面内存，切换用户/项目/记录、执行epoch变化或页面销毁时清理；刷新首次仍需完整解析历史，解析过程后台进行，ready及异步写入完成后一次显示底部。历史查询不会回传给PTY；Esc返回报告不作为中断快捷键，取消/结束仍是显式操作。

固定0.166.0的 TUI 在原生 resume 后发送 turn/start 时包含默认 collaborationMode.settings.developer_instructions。这是客户端自带模板，代理将默认模式的 collaborationMode 清空，由服务端继续使用固定指令；不因模板存在拒绝普通“继续分析”，也不将客户端指令放行到模型。其他协作模式拒绝，原命令/文件/权限白名单保持。真实 exe 的回归须实际发送恢复后的第二轮，检查同一 thread、历史问答和固定 Skill 保留，不能只验证恢复画面。

每次执行的 *.rpc.enc.jsonl 加密保留 RPC 错误、turn/completed 的状态及原始错误、显式 turn/interrupt 和策略拒绝字段；脱实际 Key，不保存普通问题正文/完整请求参数。TerminalResult 也处理本次 turn/start 请求本身的 RPC 错误，避免没有 turn/started 时无限等候；失败与中断分开标记，不视为有效候选或触发自动重发。旧日志未采集的错误不推断补写。

RPC日志同时记录 turn/started，使新轮次开始会清除上一轮失败展示。服务端从已授权执行的该日志读取 turn_status/turn_error，独立于数据库中的进程生命周期状态；前端展示真实轮次结果和等待输入状态。WebSocket以完整会话状态变化推送，且先发状态再回放历史，避免长历史或进程一直RUNNING掩盖模型早已失败。终端ANSI内容原样保留，不把部分输出当完整结果。

会话仍由既有Worker、对话任务及预算管理，状态/输入/记录只绑定本人记录。app-server和TUI同受Windows Job Object生命周期控制；目录隔离、固定Skill/资料、密钥不继承平台.env；显式取消仍有效，数据库失锁按上节重连并保留CLI执行。app-server stderr脱实际Key加密，TUI输出脱实际Key和临时代理令牌。参考[官方app-server协议](https://learn.chatgpt.com/docs/app-server)；固定exe自身生成的0.166.0 schema与真实CLI/本地假provider测试作为版本验收依据，不把当前在线文档当作旧版全部行为保证。

## 原生业务调用（现行）

- 配置有效的 Windows CLI 可执行文件后，runtime 返回 available=true / execution_policy=native-v1，个人 CLI 可“保存并使用”。版本探测只用于显示实际版本及记录诊断。启动、参数或协议失败沿现有错误路径返回。实际切换由用户在设置页完成；平台不擅自将保存的CLI配置设为当前方式，不触发收费验证。
- 五类分析、独立对话及 Skill 助手沿公共 ai_client 选择 CLI。五类新绑定的分析使用原生 TUI，独立文本对话、Skill 助手和旧未绑定任务经 codex exec 执行。历史缺调用方式按 API 解释。任务快照固定本人模型、强度、调用方式和版本。
- 业务CLI直连所配模型服务，保留CLI原生多轮、HTTP/SSE重试、上下文压缩和等待默认值；平台不增加总时限、不调用测试网关、不限制只发一次模型请求，也不在CLI失败后自动换API或重新提交任务。CLI本身仍可能有空闲超时/重试上限，不能宣称供应商或CLI无限等待。一个Worker槽代表一次CLI进程生命周期，实际模型调用数仍未知。
