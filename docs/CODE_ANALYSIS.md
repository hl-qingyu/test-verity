# 代码分析正式实现

## 现行规则

支持代码缺陷、需求符合性及前后端一致性检查。v3 候选返回目标判断与证据，平台计算文件覆盖及总体状态。前后端一致性保留可读的双角色代码门槛。旧 v2 报告按冻结契约处理。

新任务使用契约 v3。平台按固定来源统计文件可读状态并计算总体结论，模型返回目标判断和绑定证据。CLI 按索引读取固定代码和资料。历史 v2 记录沿用冻结契约。

配对导入支持 v3 输入与 v3 候选或成品报告。同次分析的完整 v2 固定输入也可和 v3 结果配对。调用标识与所有目标、证据及引用仍须匹配。模型 v3 候选的调用链 `inputs` 和 `outputs` 偶尔以纯字符串列表返回，平台按原顺序用换行合为文本后再执行完整校验。原发起人可免费重新校验已保存候选，原始响应和校验记录保留。

使用 Codex CLI 启动代码分析后进入该记录的「历史对话」，首轮校验通过后可返回查看发现、固定证据和人工处理入口。续聊报告按轮预览，并以该记录的固定代码、资料和契约核对。[CLI 实施契约](AI_CODEX_CLI_IMPLEMENTATION.md)

## 功能与入口

代码分析页顶部为新建代码分析、导入代码分析、历史对话。左侧分析记录，中间当前记录的发现列表（每页10条）、目标筛选及目标完成状态，右侧固定来源与资料。分析记录每批50条继续加载，列表查询只取摘要，不把全部源码随轮询反复加载。

新建分析按名称、三项检查目标、代码来源/文件树、需求及原型资料Tab、范围确认、补充关注点与个人AI说明组织。来源分GitHub和本地，同次只用一种来源方式，可选择多个已登记仓库/本地来源；WEB和FLUTTER均为客户端，BACKEND为后端，类型由服务器从项目登记读取。

- Bug允许单端；需求符合性需要可读业务依据。仅勾选需求符合性而无资料时不创建；多目标可保留该目标材料不足的结果。
- 勾选前后端一致性必须实际选择后端与前端/移动端文件；缺一端拦截整个任务，资料不能替代代码。两端齐全仍不代表接口已配对。
- 文件树支持目录/文件选择、搜索、选择当前可见文件、清空及只读预览；目录按需展开，每级分批显示200项。路径索引和选中Set避免渲染时重复扫描完整文件列表。目标切换保留选择；来源方式、版本和连接切换使代码选择失效。
- GitHub通过固定GET白名单解析分支/完整提交，再从该提交树取得选定blob，校验内容SHA。支持Java、Python、Dart、SQL及现有常见文本格式，不沿符号链接读取。
- 本地代码沿用浏览器目录授权和排除规则，只在提交时读取所选文本并校验哈希。服务器不访问用户磁盘路径。所选代码明确保存到本项目并发送本人的AI服务，不把项目设置中的一般本地读取默认变成上传。
- 已选代码、资料与附件不再按16MiB合计大小拦截；单文件文本约束、二进制/凭据路径及构建依赖排除保持，不静默截断。实际模型或中转仍可能因容量或链路问题拒绝。
- 原型资料链接可先读取已验证 XETA 静态原型站的页面目录，搜索/分组选择具体页面并预览；Worker 只读所选页面 HTML 原文和原型说明，固定内容哈希。链接地址或目录变化拒绝，未执行脚本或抓取外部资源，按 PARTIAL 输入；其他站点链接不支持解析。代码分析与需求分析复用同一受限读取器，不把说明称为人工确认规则。

## 三类分析内容

Bug详情突出代码预期、执行路径与错误原因；需求符合性展示固定依据与实现对照；一致性展示接口关联依据及双方字段/行为比较。同根因多目标仍是一条发现，详情按目标分区。证据、行号、类型、快照及调用关系来自校验后的固定输入。

严重程度、证据状态、人工处理各自独立。处理状态为待处理、已确认、已处理、误报、需补充证据；非待处理需要说明，通过revision检测并发修改，保存审计历史，不修改原始模型报告。保存处理后保留原列表筛选与页码。

提供整份记录Markdown、input.json和report.json导出，不受当前页或目标筛选限制。旧v1报告不自动转换、不显示为可继续执行的v2报告。

## 后台执行与权限

`modules/code_analysis/service.py`负责项目权限、幂等入队、取消、人工重试及处理。`sources.py`只读固定来源并组织完整固定输入，`execution.py` 按冻结版本生成模型请求，由 `app.chat_worker` 执行。`contract.py` 校验结构、目标、覆盖和证据引用。

创建时保存Skill/契约全文、SHA-256和版本。Worker准备完成后保存固定input；已取得固定input的重试复用原快照并生成新的request_id，历史报告不覆盖。尚未准备完成的失败记录按原选择重新读取固定Git提交或已保存本地文本。本人AI配置名称、模型、版本单独固定，不保存地址/密钥到报告。

AI完整响应返回后，原始响应先原子写入本机私有目录`backend/storage/code-analysis-results/`，目录由`CODE_ANALYSIS_RESULT_PATH`覆盖；文件名为`code-analysis-{task_id}-ai-candidate.txt`。随后才解析、规范化、校验并再次复核账号/任务/来源/配置，正式report仍仅在全部通过后入库。未取得完整AI响应时不生成文件；取消、撤权或配置变化时返回的候选可保留用于排查，但不得作为成功报告。项目成员可从失败或完成记录下载原文，接口重新校验项目权限；候选正文不进入日志、详情API或对话。单任务每轮仅一个文件，人工重试使用新任务ID另存。

代码证据仅在同一固定来源和文件内能唯一定位完整原文行时才校正坐标，具体规则按报告版本执行。校正记录包含证据标识和坐标。发起人可对证据或契约校验失败且已有候选的原任务免费重新校验。平台复核项目、来源和个人配置，通过该记录的完整契约校验后将报告写入同一记录，保留原始候选、原失败码、操作人和时间。重复提交返回已保存的结果。

任务持久化后离开页面继续执行。取消仅限发起人；失败/取消只能人工重试，使用重试者个人AI，不能回退平台配置。执行前、进度回调、保存结果前重新核查账号、项目、来源授权和AI配置版本。取消/撤权/配置变更期间返回的结果不保存为成功。重启将正在执行的轮次标为失败，避免自动重放可能计费的调用。

Worker在需求分析、代码分析、需求对话、代码对话之间轮流领取，避免一种队列永久优先。它仍是单执行进程，不增加任意脚本执行器或Agent框架。

## 配对导入

选择input.json和report.json，每份最大16MB；前端展示调用标识、来源、版本、目标、发现概览，后端对两份原始JSON严格校验。拒绝重复JSON字段、非法枚举、额外人工状态、错误行号/摘录、未读引用、漏覆盖、目标关联及状态不一致。

资料按source_id关联系统已有资料，文件需指定版本；资料栏目需匹配。图片/PDF引用要求对应固定文件版本和内容哈希，不从输入URL下载附件。代码来源可以是外部分析产生的固定快照，明确标注为用户导入；内部引用校验不代表已自动与真实仓库或整个原件全文比对。

导入不调用AI。相同项目中相同输入/结果摘要重复导入返回原记录，不覆盖其人工处理；不同结果保留为新记录。项目权限在读入前后复核，不能跨项目查看、处理或导出。

## 独立历史对话

每条完成的代码报告有独立对话历史，可引用某条发现提问，使用提问者个人AI。上下文仅包含本报告固定输入、结果、处理快照及已完成历史；不混入需求聊天。每条记录同一时间只允许一轮活跃对话，幂等请求ID防重复计费，只有本轮发起人可取消。

回答只保存为对话，不自动新增、关闭或改变发现。本轮没有增加附件上传或自动补读能力；涉及图片/PDF时对话仅能使用报告已有文字观察，不能假称重新看过未附加的图片。上下文超限明确拒绝，不静默删掉历史。

## API

基路径：`/api/projects/{project_id}/code-analysis`。

| 方法/路径 | 职责 |
| --- | --- |
| GET 空路径、GET /{id} | 分页记录摘要、固定输入及完整详情 |
| GET /options | 项目来源、本人连接、固定资料版本、本人AI元数据 |
| GET /github-scope、GET /github-file | 固定提交的安全文件树与只读预览 |
| POST 空路径 | 提交代码/资料选择，异步入队 |
| POST /import | 配对导入，不调用AI |
| POST /{id}/cancel、POST /{id}/retry | 发起人取消、当前用户人工重试 |
| POST /{id}/revalidate | 原发起人在同一失败记录上手动重新校验已保存的AI候选，不调用AI |
| POST /{id}/handling | 修订号保护的独立人工处理 |
| GET /{id}/export?format=markdown/input/report | 完整记录导出 |
| GET /{id}/candidate | 下载该AI任务已返回的原始候选文本；仅在完整响应成功返回后存在 |
| GET/POST /{id}/chat | 分页历史、异步提交对话 |
| POST /{id}/chat/{turn_id}/cancel | 发起人取消对话 |

前端统一通过`api/http.ts`，业务解析及错误映射在`codeAnalysisApi.ts`；不直接访问AI/GitHub密钥。
