# requirement-analysis v4.0.0 调用与导入

## 现行规则

规则包位于 skill/requirement-analysis，调用输入与结果格式以已冻结契约为准。规范及引用文件在任务开始时作为快照保存。

加载SKILL.md及contract.md，按契约 v4 审查需求风险与未完善内容。调用前由执行程序保存实际input.json，模型只返回完整结果JSON，再保存为report.json或risk-report.json；不要让模型重造原始输入。完整合成示例见examples/input-v4.json 与 examples/output-v4.json，不能把示例当成真实分析结果。

正式系统的“需求分析 → 导入分析结果”同时接收两份JSON，每份最大16MB；支持契约 v3 和 v4 的同版本配对。v4 可导入模型候选或成品报告。平台为候选计算 coverage 及 outcome，并校验成品报告中的这两项。填写报告名称，为每份来源（如P1）关联当前项目已有的需求资料/原型资料；文件资料须选择实际使用的固定版本。没有对应资料时先在资料模块登记。图片/PDF不用再次上传，也不需要attachments目录。

系统校验调用标识、字段、引用和证据与固定输入的对应关系，再整份入库。来源类别由input.materials.origin及对应系统栏目识别，不额外选择资料用途。图片观察与人工来源关联仍须人工核对，不冒充模型实际读取原件的证明。

入库后可查看分析记录、功能清单、风险清单、完整报告、输入原文与系统原件；可导出input.json、report.json及包含人工处理的Markdown报告。风险处理状态/结论单独留痕，不改写原分析结果。相同输入与结果重复导入返回已有报告；若关联来源不一致则拒绝，不静默覆盖。

平台后台分析可使用本人配置的 Responses API 或 Codex CLI。直接使用规则包时，由调用方负责读取权限、固定资料和模型调用。只提供 GitHub 或原型链接时，需先取得授权范围内的正文。

历史报告继续使用保存时的契约版本。模块入口、人工处理与验证边界见[需求风险报告](REQUIREMENT_RISK_REPORTS.md)。
