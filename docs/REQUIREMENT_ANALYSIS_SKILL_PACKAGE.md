# requirement-analysis v3.0.2 调用与导入

加载SKILL.md及contract.md，按契约3审查需求风险与未完善内容。调用前由执行程序保存实际input.json，模型只返回完整结果JSON，再保存为report.json或risk-report.json；不要让模型重造原始输入。完整合成示例见examples/input.json与examples/output.json，不能把示例当成真实分析结果。

正式系统的“需求分析 → 导入分析结果”同时接收两份JSON，每份最大16MB；仅支持契约3。填写报告名称，为每份来源（如P1）关联当前项目已有的需求资料/原型资料；文件资料须选择实际使用的固定版本。没有对应资料时先在资料模块登记。图片/PDF不用再次上传，也不需要attachments目录。

系统校验调用标识、字段、引用、逐片段覆盖、证据定位和摘录与输入一致性，再整份入库。来源类别由input.materials.origin及对应系统栏目识别，不额外选择资料用途。图片观察与人工来源关联仍须人工核对，不冒充模型实际读取原件的证明。

入库后可查看分析记录、功能清单、风险清单、完整报告、输入原文与系统原件；可导出input.json、report.json及包含人工处理的Markdown报告。风险处理状态/结论单独留痕，不改写原分析结果。相同输入与结果重复导入返回已有报告；若关联来源不一致则拒绝，不静默覆盖。

AI自动调用暂未接入，也不支持v2兼容运行。此包不是HTTP服务，不包含密钥、用户资料或资料采集器。只传GitHub/原型链接而未提供正文，Skill不能自动读取；调用模型、读取权限和资料外发仍由调用方负责。

当前两份文件在本次回归中已验证可被v3解析，完整模型效果仍须人工审阅。

3.0.2增加了结果可读性约束：风险描述必须先写具体业务场景，再说明缺少的规则；影响要落到具体实现/验收分歧；待确认事项要能直接回答；完善建议尽量给出可直接补入需求的规则草案和示例。该调整只影响后续模型生成文字，不改变v3字段、证据边界或历史报告。
