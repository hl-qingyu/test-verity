## 页面与流程

2026-09-15修复无分类建议无法采纳：任务64的6个功能classification_key均为空，原弹窗默认“建议分类”且后端要求分类导致采纳422。现无建议时默认待归类，后端允许category_id为空保存验收点，人工指定分类优先；不修改模型结果或自动生成分类。采纳后按返回rule_id映射提示实际新增条数。无候选的操作不显示验收点入库成功。原子性、幂等、权限和业务审核状态不变。

2026-09-15补齐完整诊断：任务详情增加“分析过程与诊断”。显示准备、读取、组织输入、发起请求、响应头、接收事件、校验和保存阶段；有真实计数和耗时，无虚构百分比。技术详情可查看请求地址/模型/配置版本/Skill摘要、字节数、连接至响应头耗时、首字节/首事件、事件与心跳计数、输出字符数、请求/响应ID、明确终止事件和上游错误分类，支持复制安全诊断。输入正文、密钥、模型思考和上游错误原文不进入诊断或日志。

诊断随任务持久化，不再依赖被重启覆盖的日志。新列diagnostics默认空对象，旧任务明确显示“未记录”，不能倒推已丢失原因。阶段变化立即保存；接收过程中每5秒有事件时更新。没有事件的等待期间可看到已用时，但不能将无更新认定为模型卡死。取消后后续事件触发停止本地接收；完全无数据时仍受当前网络读取超时约束，不承诺立刻终止上游计费。网络600秒是socket等待设置，不是总任务时长；HTTP504或错误事件中的上游时限单独记录，不再混为本平台超时。

HTTP错误正文只在内存中有界读取用于识别，流式error/response.failed/incomplete保留事件类型、白名单错误码、诊断指纹和可识别请求ID。未知原因保持unknown，不能当成已确认超时。只有错误文本明确表达超时时长才提取数字；上游状态与响应HTTP状态分别展示。结果字段校验记录字段路径/类型，引用校验记录安全规则名称，不保存错误输入。JSON/编码异常、无完成事件、大小保护、拒绝、连接超时、取消、Worker中断均分别可定位。

验证包括本地HTTP模拟服务→真实Responses流解析→真实数据库Worker→任务API的成功/失败闭环；模拟失败含900秒超时描述，实际测试无需等待900秒，也未使用用户资料调用中转。迁移20260915_23真实中文COMMENT和Alembic一致性通过。

2026-09-15新增GitHub具体文件选择：勾选原型资料后显示其配置范围内的文件清单，默认全选，支持路径搜索、全选/清空、逐项选择及大小提示。每份已选GitHub资料至少选一文件；搜索不清除隐藏选择，全选/清空作用于全部文件。本次选择不改资料配置、不自动补读依赖；需要相关脚本时由用户一并勾选。任务详情保存并展示实际文件范围，重试带回原选择。

2026-09-15弹窗UI调整：复用平台固定标题/滚动内容/固定操作栏布局，资料分区和卡片间距统一，选择项有背景及边框提示；版本、连接和用途使用form-field/FormSelect，补充关注点全宽主题textarea，窄屏单列。提交、选择和费用确认规则不变。

需求分析顶部“新建需求分析”选择两类资料及用途，可全选/清空、选上传版本、选本人GitHub连接并填写关注点。显示个人AI配置和Skill版本；明确点击开始才发送内容并可能计费。用户于2026-09-15要求移除重复的“建议分类”按钮，分类建议在分析结果中审阅。

“分析范围与记录”查看分页任务列表；结果弹窗依次展示全部功能及验收点、待确认问题、AI建议、来源差异和读取完整性。功能粒度遵循Skill v2，例如查询包含搜索/筛选/重置；无完整验收点的功能保留待补充。AI建议提供理由和取舍，不随验收点批量采纳。建议要成为正式需求，先人工判断，再使用已有验收点维护流程整理。

可选功能、验收点和目标分类。建议新分类如同名冲突，必须明确选择现有分类，不静默合并。采纳在项目锁与revision校验下同事务完成；相同采纳请求返回原结果，新请求重复选已采纳候选返回409。不会覆盖旧验收点，也不会把建议或分析结果写为已确认/测试通过。

采纳后的验收点通过analysis_id及analysis_candidate_key保留原任务关联。来源对照可回查当次原文和固定上传原件；人工修改业务、增加人工来源不移除初始任务证据。资料删除影响统计包括已采纳的AI候选引用；删除资料保留历史，新采纳拒绝已删除来源。

## 实际资料读取边界

| 来源 | 已接入处理 |
| --- | --- |
| TXT/Markdown | 完整文本解码，按字符分片定位，全部片段发送；不访问正文中的链接 |
| DOCX | 安全XML读取正文段落及表格文字；含内嵌图片标PARTIAL并提示另选图片资料 |
| XLSX/XLS | 读取全部工作表单元格，保留工作表/单元格定位，不执行公式和宏；图像、图表等未作为已读内容，标PARTIAL |
| PNG/JPG/JPEG/WEBP | 传入实际图片附件；模型必须支持图片，不能以连接测试成功冒充图片能力验证 |
| PDF | 传入实际PDF附件；依赖本人模型/中转文件能力，未提供本地页码提取时只允许整份定位与观察描述，不伪造原文摘录 |
| GitHub原型 | 使用发起人连接与项目仓库授权交集，固定当次分支提交并读取已选HTML/CSS/JS等文件正文；blob内容校验Git对象SHA。不执行HTML/JS，不从源码推定后端业务已实现 |
| 原型链接 | 列表说明“链接尚未采集页面正文”，当前不能勾选发起；仅地址不冒充网页快照 |
| 旧DOC | 提示转换DOCX/PDF；不能解析时明确未读，无可读内容则失败 |

资料页的“页面/交互说明”一起作为证据片段，补充关注点仍低于平台结构和权限。未选择的附件、源码依赖不会递归读取；本地代码继续只在浏览器保存，不进入本次范围。

不新增来源文件数量/大小限制，不发送前N段冒充全文。一次任务完整输入发起一次模型请求，暂不自动拆成多次付费请求；超模型上下文需明确失败并由用户调整范围后重试。现有Office压缩包安全校验保留。模型输出上限32000 tokens、响应读取保护16MiB、网络等待600秒；高推理强度、较大输入或供应商限制可能导致未完成，不能报成成功。未来如需分批分析，需同时设计跨批功能去重/冲突合并和费用提示，不能简单按段各自入库。

文件和图片实际通过Responses的input_text/input_image/input_file协议传入，store=false、stream=true，以SSE流接收且只接受完成事件，不提供tools、不跟随重定向或环境代理，地址继续使用后端白名单。协议参考[官方文件输入说明](https://developers.openai.com/api/docs/guides/file-inputs)与[图片输入说明](https://developers.openai.com/api/docs/guides/images-vision)；第三方中转兼容性未做真实验证。

## 任务执行与权限

- 状态：QUEUED排队→PREPARING准备→RUNNING分析→COMPLETE完成/PARTIAL部分完成/FAILED失败；取消为CANCELLED。Skill BLOCKED映射任务失败，未决业务问题可以与分析完成同时存在。
- 仅使用发起人个人配置，执行前及返回后校验用户有效、项目权限、资料可用及配置版本；配置变化不自动换模型。GitHub连接也固定版本并重复校验。没有个人配置直接拒绝，管理员也无平台密钥回退。
- 同项目、同用户、同request_id及相同输入只创建一个任务；不同输入复用ID返回409。任务列表20条分页，不加载大文本快照。
- 取消只允许发起人。取消阻止后续开始调用和结果采纳，已经发送的上游请求可能继续并产生费用；上游返回后若已取消则丢弃结果。
- 独立单Worker使用PostgreSQL会话咨询锁确保单实例，数据库行锁领取任务。进程退出后，下次启动把遗留PREPARING/RUNNING标为失败，说明结果未知，不重新执行可能已计费调用。排队任务继续等待。
- 项目成员可读取任务/证据并采纳；再次分析或重试为新的、有关联的任务，用当前操作者自己的配置和明确选择的连接。未获得项目访问权限不得读取历史结果。
- API及Worker不记录提示词、密钥、源码或上游正文到日志；错误以安全码展示。模型结果必须通过结构、状态、标识、位置、摘录及交叉引用校验，不以模型自报合规替代后端校验。语义正确性和无遗漏仍需人工审阅。

## 本地运行

在backend目录，沿用已有.env和虚拟环境，不重建账号或密钥：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

另一个后台进程启动Worker：

```powershell
.\.venv\Scripts\python.exe -m app.analysis_worker
```

前端在frontend目录运行npm run dev。API和Worker分别运行，关闭页面不影响Worker；只有API而没有Worker时，任务保持排队。Worker第二个实例会明确退出。当前开发启动不创建Windows系统服务或开机自启任务。

## 2026-09-15：中转60秒504与流式接收

任务26已生效单文件选择（648902字符、41片段），但中转在60.5秒返回HTTP504；不是本平台600秒网络等待触发。非流式等待完整结果可能触发中转等待阈值，具体中转超时机制尚无其服务端日志确认。分析请求改为stream=true，使用标准SSE解析，只读取response.completed中的完整响应；中间增量不入库，断流/未完成/失败/拒绝分别报错，不自动重试或降档。固定文字连接测试仍stream=false。兼容中转返回完整JSON，但不发第二次请求。JSON请求使用UTF-8减少中文转义膨胀，内容不裁剪。

共享错误映射区分502网关连接、503不可用、504网关超时；日志不再把分析错误误标probe，不保存上游正文或密钥。任务19/26历史保持原记录，没有代用户重试。流式不能保证解决中转硬性总时限、首事件等待或上游过载；再次504需要结合中转日志核对。协议依据：[OpenAI流式响应说明](https://developers.openai.com/api/docs/guides/streaming-responses)。
