## 目标与数据位置

用户要求在原型资料增加上传本地文件目录，后续 AI 分析可选择目录内文件。

建议采用上传副本：用户通过系统目录选择窗口选取本机文件夹，平台保留相对路径、文件内容和固定版本，供当前项目成员按现有资料权限使用。一次目录上传形成一份资料，而非把每个文件拆成互不关联的资料。服务器不接收或保存用户电脑的绝对路径，也不持续读取本机目录。

这与项目设置中已有的“本地代码”不同：后者的目录句柄和历史保留浏览器本地。本方案不改变该功能。

## 页面与操作

沿用原型资料现有两栏和主题组件，在顶部上传入口旁增加“上传目录”，不更名或重排已有菜单。方案确认后同步两份总 HTML 原型，再按原型开发正式页面。

上传弹窗从上到下为：

1. 资料名称、所属分组、页面 / 交互说明。名称默认使用所选目录名，可修改。
2. “选择目录”主题按钮，调用系统文件夹上传选择窗口；展示目录名，不展示虚构的绝对路径。
3. 可展开、可勾选的文件树，显示相对路径、文件数和总大小；支持目录选中、全选、清空。默认选中支持的文件，用户可排除不需要上传的内容。
4. 被排除及不支持的文件数量与原因；选中的文件才上传，不能只隐藏后仍传送。
5. 固定底部“取消”“上传目录”按钮，以及实际完成文件数 / 字节数、校验中和失败提示。不显示虚构百分比。

原型资料左栏以一条“本地目录”资料显示。右栏显示说明、当前版本、文件树，支持查看文件、下载、版本历史、上传新版及原有逻辑删除。文本按相对路径查看；HTML 的预览边界沿用平台隔离规则，不增加运行完整目录站点的能力。

上传新版需要重新选择目录，提交完整的新目录快照。新增、修改、删除只影响新版本；旧版本与已有分析依据保持。更名或文件移动按新版本中的真实路径展示，不推测重命名关系。

## 文件与失败规则

建议首期支持 HTML/HTM、CSS、JS/TS/JSX/TSX、Vue、JSON、Markdown、TXT、SVG 及现有 PNG/JPG/JPEG/WEBP 图片。页面和说明 / 批注文件可以同时上传及选择；不把脚本执行后的内容当作已读取。

选择窗口返回文件清单后，先在页面展示可上传范围。凭据、私钥、版本控制目录、依赖目录等按现有本地文件排除规则明确排除；其他不支持格式显示原因，不静默截取前 N 个文件或截断正文。实际上传失败必须明确提示。

服务端重新验证相对路径、同版本路径唯一、扩展名、内容、字节数、哈希和项目归属；拒绝绝对路径、路径穿越以及与申报清单不一致的文件。文件名不作为私有存储路径直接使用。

完整上传并校验通过后才发布可选的新版本。取消、缺文件、校验失败或存储失败不能产生可用于分析的半份目录，也不能替换当前成功版本。上传请求 UUID 防止重复保存；同一 UUID 携带不同内容返回冲突。网络超时不自动重发，先查询是否已完成。

## AI 分析选材

需求分析、代码分析的原型依据、用例分析及用例生成，均从现有资料选择区选择“目录资料 → 固定版本 → 文件树”。不能仅因选中目录资料就把整个目录无提示地发送给模型。

文件范围支持目录勾选、单文件勾选、全选、清空和已选数量。进入分析准备时将选中的目录展开为该版本的明确文件路径，固定版本 ID、路径和内容哈希。更新目录、切换项目或修改选择时，清除失效范围并要求重新选择。

模型输入为所选文件的完整内容，证据位置包含目录资料、版本和相对路径；图片沿用现有附件能力。读取说明区分已经提供的文件与未选择的依赖，不声称已经理解运行后页面。

变更分析增加本地目录原型的旧版本 / 新版本选择，复用已确认的旧基准 / 新目标读取规则，并按固定相对路径辨别新增、修改和删除。历史用例生成的维护模式同样保留固定的旧版本依据。

上传、预览和选择不自动启动 AI。开始分析仍使用操作者本人当前 AI 配置、现有后台任务和人工确认流程。固定输入重试读取原目录版本及原文件范围，不换成当前目录内容。

## 权限、接口与存储

沿用现有原型资料的项目成员读写权限及逻辑删除规则，不新增负责人或管理员专属限制。其他项目成员不能读取、下载、选择或更新本项目目录。资料删除后不再出现在新分析候选中，历史依据继续按原规则鉴权。

拟接入现有 prototypes 模块，不新建独立资料中心。接口语义如下，上传传输方式在实施时复用现有请求与私有文件存储能力：

| 方法与路径（均在 `/api/projects/{project_id}/prototypes` 下） | 行为 |
| --- | --- |
| `POST /directories` | 上传并创建目录资料的首个完整版本；提交名称、分组、说明、资料库 revision、上传 UUID、相对路径清单及文件 |
| `POST /directories/{source_id}/versions` | 上传同一目录资料的完整新版本，校验资料库 revision，不覆盖历史 |
| `GET /directories/{source_id}/versions/{version_id}/files` | 返回该固定版本的完整目录清单与文件元数据 |
| `GET /directories/{source_id}/versions/{version_id}/file` | 按经校验的相对路径鉴权查看或下载一个文件 |

列表、分组、移组、排序、版本历史和删除继续复用现有能力。分析模块沿用自身已有任务接口，新增目录版本与文件路径选择，不新增另一套 AI 执行服务。

来源需能明确区分目录与单文件，版本需保留不可覆盖的文件清单和私有存储索引。沿用现有资料与版本身份；确需新增的文件索引以及字段 / 枚举调整用 Alembic 迁移，模型和真实数据库均有中文注释。旧 FILE/GITHUB/LINK、历史导入导出和固定重试保持可用，不把旧报告迁移成新类型。

## 验收

- 含多层目录、中文路径、同名不同路径文件的文件夹上传后，保持一份目录资料和完整的已选范围；取消系统选择不改变页面数据。
- 各分析可选择固定目录版本和其中部分文件；实际固定输入、导出与模型请求只包含明确选择的正文 / 图片及明确附加的说明。
- 新版修改、增加或删除文件后，旧分析及重试仍能取得原版本、原路径和原哈希；变更分析明确表达两侧差异。
- 上传重复、部分失败、非法路径、冲突、未登录和跨项目访问均有明确结果；失败不发布半份版本。
- 两份总原型与正式页面对照核验展开文件树、长路径、上传状态、失败反馈、弹窗、390px 窄屏、键盘与焦点，无遮挡或横向溢出。
- 运行对应前端请求与交互回归、UI 规范、类型 / 格式 / 构建；后端业务、架构、数据库中文注释与 Alembic 一致性检查；不以模拟 AI 结果冒充真实付费分析验证。
