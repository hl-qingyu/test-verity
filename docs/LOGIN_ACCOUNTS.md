## 页面与流程

- 未登录访问工作台，进入 `/login`。独立居中登录卡沿用原型的颜色、字体与品牌，提供账号、密码、显示密码和登录按钮。
- 登录成功进入项目概览，刷新保持登录；账号信息显示在原有顶栏、侧栏位置，侧栏底部提供退出登录。
- 工作台沿用现有导航分组；平台设置为“AI 服务”“GitHub 连接”“账号管理”。2026-10-14用户移除“原型数据”分类及占位内容；AI/GitHub已独立接入，管理员默认打开账号管理，普通账号默认打开AI服务。
- 仅平台管理员可以查询/创建/修改/删除账号、重置密码。普通用户登录后不具有这些后端权限，也不会自动获得任何项目权限。
- 账号管理支持按账号/显示名搜索、每页20条；展示账号、显示名、角色、状态、创建时间和操作。
- 创建字段：账号、显示名、角色（管理员、测试、开发、产品、经理；默认测试）、状态（默认启用）、初始密码、确认密码。
- 修改：账号、显示名、角色、状态。用更新时间检查并发修改，过期表单返回冲突，不覆盖他人修改。
- 删除：二次确认后状态变为DELETED，保留原记录和会话历史，从默认列表隐藏；不可再登录，账号名不复用。没有物理删除或恢复入口。
- 重置：输入并确认新密码，成功后该账号全部会话撤销；重置自己的密码会返回登录页。
- 修改账号名、角色或状态也会撤销全部会话。仅改显示名不会强制退出。
- 禁止删除、停用或降级当前管理员；后台同时保护最后一个启用的管理员。修改权限由事务锁串行校验，不靠按钮禁用保证。

HTML原型：`docs/prototypes/auth-accounts.html`。它可独立打开，含登录、账号列表、创建/修改/删除/重置弹窗，使用标明的演示账号；不进行网络请求，不保存密码，不把提交显示为业务执行成功。顶部视图切换条仅用于原型，不加入正式页面。

## 表结构

### user_account

| 字段 | PostgreSQL类型 | 规则 |
| --- | --- | --- |
| id | bigint identity | 主键 |
| login_name | text | 唯一；3–64位ASCII字母数字/点/下划线/连字符，首位字母数字；去首尾空白并统一小写 |
| display_name | text | 去首尾空白后1–80字符 |
| password_hash | text | scrypt哈希，包含算法参数、随机盐、摘要；不返回前端 |
| platform_role | text | ADMIN管理员 / TEST测试 / DEV开发 / PRODUCT产品 / MANAGER经理；默认TEST，USER保留历史普通用户 |
| status | text | ACTIVE / DISABLED / DELETED，默认ACTIVE |
| failed_login_count | smallint | 0–5，默认0 |
| locked_until | timestamptz，可空 | 达到5次连续错误后锁定15分钟 |
| deleted_at | timestamptz，可空 | 逻辑删除时间 |
| created_by | bigint，可空 | 创建管理员ID，自引用；初始管理员为空 |
| updated_by | bigint，可空 | 最近账号管理操作人ID，自引用 |
| created_at | timestamptz | 创建时间 |
| updated_at | timestamptz | 最近更新时间；修改请求用此值检查过期表单 |

密码长度8–128字符，不允许全空白，不自行去掉密码中的空格。密码哈希使用Python标准库scrypt：N=32768、r=8、p=3、16字节随机盐，常量时间比较。scrypt参数固定校验，不能从异常哈希中读取任意高耗时参数执行。

### user_session

| 字段 | PostgreSQL类型 | 规则 |
| --- | --- | --- |
| id | bigint identity | 主键 |
| user_id | bigint | 外键指向用户，索引；禁止删除用户时级联清空历史 |
| token_hash | varchar(64) | 会话令牌的SHA-256摘要，唯一 |
| created_at | timestamptz | 创建时间 |
| expires_at | timestamptz | 到期时间，必须晚于创建时间，索引 |
| revoked_at | timestamptz，可空 | 撤销时间 |

令牌由32字节随机数生成，原文只发给浏览器Cookie。有效期固定8小时，不滑动续期。Cookie为HttpOnly、SameSite=Lax、Path=/api；本机HTTP使用Secure=false，未来HTTPS必须设置AUTH_COOKIE_SECURE=true。退出撤销当前会话；账号停用/删除或密码重置撤销全部会话。每次鉴权同时检查用户状态。

账号初始迁移为 `backend/migrations/versions/20260911_01_auth.py`；角色扩展为 `backend/migrations/versions/20261016_39_account_roles.py`，仅更新既有字段的检查约束、默认值和真实中文注释，不新增表或改写账号角色。已有新角色账号时降级明确阻断，须管理员先决定角色调整，禁止静默合并角色。其他业务模块后续迁移见SESSION_CONTEXT，不能按初始两表状态理解当前库。

## 接口

| 方法/路径 | 权限 | 输入/结果 |
| --- | --- | --- |
| POST /api/auth/password-challenge | 公开，来源校验、频率限制 | path；返回一次性challenge_id、RSA公钥、120秒有效期 |
| POST /api/auth/login | 公开，来源校验、登录频率限制 | 加密封装内为login_name、password；返回用户公开字段并设置Cookie |
| GET /api/auth/me | 有效会话 | id、login_name、display_name、platform_role |
| POST /api/auth/logout | 校验来源，可重复调用 | 撤销当前会话并清Cookie；204 |
| GET /api/users | 平台管理员 | page、search；返回items及total，每页20条 |
| POST /api/users | 平台管理员、来源校验 | 加密封装内为创建字段及两次密码；201 |
| PATCH /api/users/{id} | 平台管理员、来源校验 | 账号/显示名/角色/状态和原updated_at；200 |
| DELETE /api/users/{id} | 平台管理员、来源校验 | 逻辑删除；204 |
| POST /api/users/{id}/reset-password | 平台管理员、来源校验 | 加密封装内为password、confirm_password；204 |

所有变更接口要求Origin属于后端配置的允许列表。没有放开CORS，不接收客户端自选权限或项目范围。账号字段唯一冲突返回409；过期表单返回409；未登录401；普通用户管理操作403；输入错误422；数据库不可用503。

账号不存在、密码错误和账号不可用的登录响应统一使用invalid_credentials，未知账号也进行密码哈希运算。连续5次失败锁定账号15分钟；另有每来源地址每分钟20次的进程内限制，限制地址表最多2048项并清理过期项。当前方案用于本机单进程；多进程或公开部署前需在可信反向代理做统一限流，不能直接宣称本进程计数覆盖所有节点。

验证错误响应不会回显提交的密码。账号/认证响应带Cache-Control: no-store；SQLAlchemy隐藏参数；数据库错误只返回固定失败码。接口没有输出密码哈希或会话摘要。

## 密码请求加密

三个密码入口共用 `frontend/src/passwordTransport.ts`，实际网络请求只包含：

```json
{
  "challenge_id": "本次一次性标识",
  "wrapped_key": "RSA加密后的临时AES密钥（Base64）",
  "iv": "随机初始化向量（Base64）",
  "ciphertext": "加密请求正文及校验标签（Base64）"
}
```

1. 点击提交后，客户端取得指定接口的一次性标识和公钥；该请求只发送接口路径，不包含密码。
2. 浏览器原生Web Crypto每次生成新的AES-256密钥和12字节随机IV，用AES-GCM加密完整提交正文；使用RSA-3072 OAEP/SHA-256封装AES密钥。并非Base64编码或固定前端密钥。
3. 一次性标识、POST方法和目标路径绑定到加密认证数据；后端同时检查发起时的登录Cookie绑定。标识有效期120秒，原子消费一次；失效、重复提交、篡改或错用接口返回400，不回退明文。
4. 后端解密后仍按原字段模型校验，错误不返回解密内容。随后使用原有scrypt校验或保存密码哈希；不存储可解密密码，不迁移已有用户密码。
5. RSA私钥仅在当前后端进程内存中，重启生成新密钥；公钥可以公开。校验信息缓存有2048条上限和过期清理。重启时未提交的请求失效，重新点击提交即可获取新信息。
6. 当前是本机单进程方案；多Worker部署前需要共享的一次性消费机制和密钥管理，不能直接扩大进程数。后端新增固定版本 `cryptography==50.0.1`，因为Python标准库没有本方案需要的RSA-OAEP和AES-GCM原语；前端不新增依赖。

本机127.0.0.1的浏览器安全上下文可使用Web Crypto；在不支持安全加密的环境中不发送密码、不回退明文。**当前服务仍是本机HTTP；正式/局域网使用仍需要HTTPS**。字段加密不验证HTTP下收到的脚本与公钥，也不保护未加密的会话流量，不能替代TLS。开发者工具的Network请求体为密文，但本机调试器仍可能查看输入框/加密前内存，本功能不宣称能向控制浏览器的人隐藏其输入。

算法接口依据：[Web Crypto encrypt](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt)、[cryptography AES-GCM](https://cryptography.io/en/latest/hazmat/primitives/aead/)、[cryptography RSA-OAEP](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/rsa/)。

## 启动与配置

数据库配置从固定位置 `backend/.env` 读取，不依赖启动时工作目录；该文件被Git忽略，并限制为当前本机用户可读写。本地已有配置，不要再次复制示例覆盖它。文档不记录实际数据库密码或管理员密码。

```powershell
# 在 backend 目录执行
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

`--no-proxy-headers`避免客户端伪造转发地址绕过本机来源限流。默认允许浏览器来源为http://127.0.0.1:5173、http://localhost:5173；改变本机访问地址需对应调整AUTH_ALLOWED_ORIGINS，不能用任意Origin通配。

初始管理员 `admin` 已按用户指定密码创建，不要重复初始化。其他空环境首次初始化可运行：

```powershell
.\.venv\Scripts\python.exe -m app.init_admin
```

命令使用隐藏输入设置密码；管理员已存在时拒绝覆盖。未开放注册、找回密码和公网初始化入口。
