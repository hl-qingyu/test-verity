# 系统架构

登录后的各菜单页和需求历史对话使用会话内存恢复浏览状态，包括各页适用的搜索、筛选、分页、活动标签和所选记录。项目页面按当前项目隔离，切换项目重置项目页状态。平台设置、Skill 管理和 AI 结果验收按登录会话保留。刷新或退出清空缓存。概览定向链接和指定资料链接优先使用链接目标。页面重新请求业务数据并复核权限，缓存只保存已选浏览状态，编辑草稿、审核勾选和弹窗重新初始化。

原生CLI界面现行复用用例生成“历史对话”区域；返回报告缓存同一终端画面及连接，重连按cursor补新增帧，首次恢复后台解析后直接显示底部。缓存只在当前页面内存中，切换用户/项目/记录及新执行隔离；不改变后台模型生命周期。详见[用例生成现行规则](CASE_GENERATION.md)。

同一CLI对话的多份候选JSON保存在原CaseGenerationRun下的独立CaseGenerationBatch轮次，使用独立审核命名空间，原文与处理记录保留。保存不创建对话或调用模型；前端在原历史区域保存，再按轮次进入原审核入库流程。已有自动捕获原文可补来源而不重复保存；未审核的旧独立副本核验后归回，原副本逻辑归档。

CLI大文件阅读复用`integrations/cli_reading`在本任务目录生成无损、有界正文及内嵌图片的阅读表示；原件/Skill/历史保留，读取仍只由标准filesystem服务提供，无自定义MCP或业务拆批/自动模型重发。原生TUI及非交互大文件共用；首次构建后通过认证摘要核对并复用阅读目录，恢复指引复用历史、仅按需补读。详见[CLI实施契约](AI_CODEX_CLI_IMPLEMENTATION.md)。

本文说明当前代码结构和开发边界。编码细节见[代码规范](CODE_STANDARDS.md)，界面规则见[界面规范](UI_STANDARDS.md)，模块入口见[文档目录](README.md)。原累计记录保存在[历史副本](archive/ARCHITECTURE_HISTORY.md)。

## 工程组成

| 部分 | 职责 |
| --- | --- |
| frontend | React、TypeScript和Vite应用，页面、主题控件、业务请求及前端测试 |
| backend/app/main.py | FastAPI应用、异常处理、日志和健康检查 |
| backend/app/chat_worker.py | 单个分析与对话调度进程，使用线程池和数据库调用预算 |
| PostgreSQL | 账号、项目、资料版本、用例、任务、报告、对话和人工处理 |
| backend/storage | 上传原件、部分原始结果、修订记录、规则备份和私有诊断文件 |
| skill | 五类业务分析规则、结果契约和引用文件 |

当前使用单API进程、单后台调度进程。账号挑战和部分限流保留进程内状态；后台通过PostgreSQL咨询锁取得调度权，再按调用预算并发执行。扩容前需要重新设计共享状态，不能直接增加进程数。

调度锁使用独立NullPool连接和AUTOCOMMIT，不放回业务连接池；每5秒在同一连接保活，PostgreSQL只对该连接启用60秒空闲/空闲事务超时。Worker失联或退出而TCP尚未断开时，数据库自行回收会话并释放锁。重新连接必须重新取得锁；暂时被其他连接占锁或仍有活跃调用时，Worker等待重试，不直接退出或强制终止其他连接。业务连接不设置该空闲回收时间，CLI不因此被取消。

## 后端分层

依赖从入口和业务层指向基础层，不能反向或循环依赖。

| 层 | 负责 | 限制 |
| --- | --- | --- |
| main、api/router | 应用启动和模块装配 | 不写业务流程 |
| api | HTTP身份依赖、来源校验、密文适配 | 不承载业务流程 |
| modules/*/router | 接收和校验请求，调用服务，返回协议结果 | 不写SQL，不直接发外部请求 |
| modules/*/schemas | 输入、输出和纯数据校验 | 不访问数据库或网络 |
| modules/*/service及业务辅助文件 | 权限、业务规则、版本检查、事务和任务状态 | 不依赖HTTP层或其他模块路由 |
| integrations | AI、GitHub、原型采集等固定外部协议 | 不依赖业务模块、数据库或ORM |
| security | 密码、密文、凭据、限流和来源内容检查 | 不依赖业务服务 |
| db | 数据库连接、会话生命周期和模型 | 不调用业务服务或外部协议 |
| core | 配置、错误类型和日志 | 不依赖上层 |

服务之间可通过明确的公开函数或数据契约复用能力，禁止导入其他模块的router。纯校验可以复用基础协议校验函数，但不能借校验执行外部读取。不要增加只做转发的仓储层、工厂或接口。

| change_analysis | 新旧来源对照、影响分析、人工处理和历史兼容 |
| case_generation | 用例生成、建议草稿、澄清、审核和逐条入库 |
| case_analysis | 用例质量/需求对照、修订草稿和后台应用 |

各模块保留自己的引用校验、审核规则和事务。共用AI协议不合并这些业务规则，也不改变模块权限。

## 分析执行

1. API核对登录用户、项目权限及本次选择，读取授权资料并保存固定输入。
2. 任务记录保存输入、分析规则、来源绑定和调用方式。需求、代码和变更分析入队；用例生成和用例分析先准备，确认后入队。
3. 后台取得调度权和调用预算，重新核对操作者与来源权限，使用该用户的AI配置执行。
4. 保存原始候选，执行本模块的结构、项目和引用检查，再保存正式报告或错误。
5. 人工处理单独记录。修订原始候选不调用AI，不覆盖原响应和成功报告。

用例生成的问题建议逐条隔离，其他有效建议可继续审核。需求、代码、变更和用例分析修订后仍执行完整模块校验。查看报告、认可结论、应用用例和实际测试是不同操作。

用例生成的审核入库在当前请求中逐条提交，一条失败不撤销其他成功项。用例分析应用仍由后台处理。旧排队应用和旧分批任务仅按兼容逻辑读取处理，不恢复为新任务默认流程。

取消、重试、幂等范围和修订号按各模块规则执行。关闭网页不取消后台任务；进程退出或失锁后不能把未知是否已完成的收费调用直接重发。

数据库连接故障与CLI执行分离：调度器暂停领取并重连、重新取得调度锁，已领取的CLI继续运行并保留预留。CLI完成响应先以调用预留UUID加密原子落盘，再执行原模块校验与保存；数据库恢复后只重试结果交付，不重发CLI或模型请求。重启时先处理尚未交付的结果，再标记无法恢复的旧任务；只有启动标记而无完整结果的尝试不自动重发。恢复保存仍重新检查任务身份、权限和配置版本；用户取消、失权及CLI自身失败按原流程处理。

## AI协议与工具

业务执行通过 `integrations/ai_client.py` 显式选择API或Codex命令行，不自动回退到另一方式。任务固定调用方式；旧记录未保存方式时按API解释。

API统一复用Responses请求、完整流接收、结果提取和错误诊断。分析、对话和规则助手不设置平台总时长或读写等待上限；模型列表、来源读取和连接测试仍有各自有限等待。

Codex命令行在后端Windows运行，使用配置的可执行文件，允许原生多轮请求、内部重试和上下文压缩。大输入保存在任务私有目录，由受限只读工具读取本次输入文件；没有任意命令、脚本、数据库或其他用户文件读取入口。图片按相应通道传入，PDF使用API。

CLI 文件读取复用 MCP 项目的标准 filesystem 服务，依赖与锁文件位于 backend/mcp，使用上游只读模式和目录限制。Python集成只负责启动配置，不自行实现文件分页、编码或MCP读取服务；需要后端Node.js 24以上。旧自写verity_input已移除。

用例生成的新 CLI 批次在原生成队列绑定原生会话，开始生成进入历史对话内的原生终端；Worker 自动提交完整固定资料和 Skill，同一 CLI 的最终完整回答回到原候选保存与契约校验，仍须人工审核入库。Windows ConPTY + xterm.js 直接显示交互式 CLI，同源 WebSocket 传输原始 ANSI 与按键，校验会话、项目和本次执行发起人，使用原生成预算和取消流程。生成完成释放进程，保留独立 CODEX_HOME、固定资料和画面；显式继续经原对话队列续接同一历史，后续聊天不自动覆盖报告。人工重试创建新会话并保留旧绑定；旧独立窗口仅回放，旧临时会话不能补恢复。真实TUI通过随机凭证保护的私有RPC代理连接本任务stdio app-server；白名单放行对话、历史和只读状态，拒绝本机命令、任意路径及权限扩展，TUI不持有模型Key。原始输出不转写；API、其他分析及旧非交互调用保持，详见[CLI实施](AI_CODEX_CLI_IMPLEMENTATION.md)与[用例生成](CASE_GENERATION.md)。

新建和人工重试的变更分析使用完整固定输入一次分析，不按静态关系或字节数筛减、拆批。旧分批说明只用于历史兼容，见[完整输入规则](CHANGE_ANALYSIS_FULL_INPUT.md)和[旧分批说明](CHANGE_ANALYSIS_BATCHES.md)。

## 权限与数据

- 项目访问由管理员、负责人和成员关系判断；负责人管理项目配置和成员，普通平台角色不自动取得管理权。
- AI和GitHub使用当前操作者自己的配置，不使用平台密钥兜底或复制历史密钥。
- GitHub只允许授权仓库的固定读取操作，不提供远端写入或任意Git命令接口。
- 上传资料、仓库内容、规则补充和模型回复均是不可信数据，不能扩大权限或作为执行指令。
- 写服务负责提交与回滚；外部读取前释放长事务，返回后再核对身份、权限和版本。
- 固定输入、原文件、原始响应、人工处理和已发布版本不能静默覆盖。
- 删除采用各模块约定的保留方式；活动任务会阻止相关删除，删除报告不撤回已入库用例。
- 数据结构只通过已审查的Alembic迁移变更，禁止启动时自动建表。模型和真实库的表、字段均保留中文注释。

配置固定读取 `backend/.env`。`AI_ENCRYPTION_KEY` 同时用于现有AI及GitHub凭据，迁移或重启时须保留原值。数据库、私有文件和原主密钥应作为一组备份和恢复。

## 前端与原型

`App.tsx` 装配业务路由，`Platform.tsx` 装配平台设置。请求复用 `src/api/http.ts`，业务模块负责本模块类型检查和错误文案。

复用主题控件：下拉用FormSelect/Select，表单用Form，文件入口用FilePicker，页码跳转用PageJump。具体键盘、焦点、弹窗滚动和窄屏要求见[界面规范](UI_STANDARDS.md)。

已确认总原型为项目根目录的 [verity-prototype.html](../verity-prototype.html)。后续页面、弹窗、交互和业务说明均在这个文件上修改，不再修改项目外的旧文件。[审阅副本](prototypes/verity-requirement-risk-review.html)仅作副本，不能反向覆盖主文件。菜单、字段和交互变更需按用户确认执行。原型右侧[业务说明](prototypes/verity-business-rules/README.md)描述当前实现，交互仍使用演示数据。
