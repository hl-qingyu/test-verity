## 1. 目标与工作流程

测试人员拿到需求文档和原型，对每个功能检查遗漏、不合理、不完善之处，形成有依据的风险清单，与产品沟通后人工记录确认怎么改。

工作流程：选择需求或原型 → 首次AI分析 → 校验结果并入库功能风险清单 → 关联专属需求分析对话 → 查看依据、与产品沟通 → 人工处理；需要时导出清单。

首次分析是产生系统结果的操作。后续需求分析对话、功能对话及风险追问均只保存聊天，不自动修改功能、风险、依据、处理状态或原始结果。聊天中发现值得保存的问题，必须由用户选择“添加为风险点”、补全信息并确认入库。

## 2. 页面与原型

总原型：`C:/Users/geekonup/Documents/Codex/2026-08-17/new-chat/outputs/verity-prototype.html#requirements`。审阅副本：[verity-requirement-risk-review.html](prototypes/verity-requirement-risk-review.html)。新增交互更新总原型和副本，不交付孤立页面。

### 2.1 需求分析页

- 顶部操作：新建分析会话、历史会话、导入分析结果。
- 紧凑累计概览：已入库分析次数、功能项数、风险数及高/中/低/待处理统计。某次分析的结论不能代表累计结果。
- 分析记录折叠区：显示名称、资料版本、时间、发起人、状态；可查看该次资料与结论、进入专属需求分析对话、按来源筛选累计清单。失败或进行中记录不计作零风险。
- 左侧功能范围：多次分析产生的功能项累计展示，不附加“功能对话”按钮。同名功能保留来源，不凭名字自动合并。
- 风险清单：按来源、功能、等级、处理状态筛选，每页10条，筛选变化回第一页；每条保留来源分析。
- 风险详情：问题描述、等级、依据、影响、建议、待产品确认事项及人工处理历史。处理无需先聊天。
- 不设独立报告管理、生成报告或报告快照入口，提供“导出风险清单”。原始AI输入/结果和既存历史不删除。

### 2.2 独立对话页

保留完整对话页面，不在需求分析页右侧再复制一套聊天工作区，也不在对话页复制风险处理清单。

- 左侧：需求分析对话、各功能独立对话、历史会话。
- 中间：聊天历史、输入框、发送操作；会话附件只从输入区一个“添加文件”按钮进入。
- 右侧：关联资料链接和必要的风险引用。资料不在这里预览或展开正文、章节；点击名称跳到对应需求资料页或原型资料页并定位资料。资料页展示当前管理内容，不改变本轮固定分析依据。
- 风险“追问”：打开所属功能对话并附带风险引用，不创建风险专属会话。引用可返回需求分析页对应风险详情。
- 功能“独立”指消息历史、草稿、附件和上下文独立，不代表另建页面；不再使用“总对话”名称。

## 3. 新建分析与资料范围

需求和原型至少选任意一项；没有主资料/主需求必选，各来源均可为空，只有全部未选时阻止开始。

| 来源 | 选择与依据规则 |
| --- | --- |
| 需求资料 | 从系统已有资料选固定版本；可以只选需求 |
| 原型HTML/图片 | 已有文件直接列出，合并展示不按HTML/图片分区；没有文件时不显示对应文件区 |
| 原型链接 | 读取页面树，最小菜单路径、页面及该版本已确认批注构成一个选择项；支持搜索、分组批量选择、预览、失败重试 |
| GitHub原型 | 在授权仓库范围固定提交，完整列出支持文件供搜索、全选、清空和逐项选择，不截取前N项 |

原型页面树由系统按可验证结构拆分，不由AI猜边界；不能可靠拆分的HTML按整文件选择。批注是已确认产品规则，但与页面和需求冲突时须列为差异，不能静默裁决。

分析目标可针对全部所选资料或某个功能。功能可能散落正文、章节，也可能来自旧风险/功能结果；旧结果只是定位线索，必须回到原文。不能将页面树直接视为业务功能目录。无法明确范围时提示补充，不声称已完整检查。

后续补充系统资料使用相同选择方式，只影响后续对话；初始分析输入不替换。会话上传附件不自动进入项目资料库，不跨对话自动携带；正式附件保留期限、删除和证据引用规则尚待明确。

## 4. 功能风险与人工处理

每次分析固定保存输入、结果和引用关系，结果通过结构/证据校验后入库。项目清单累计显示多次结果和人工补充风险，但原始结果保持不变。

风险定位使用“分析ID＋风险标识”，功能同样限定所属分析；同名、同编号不能跨分析串处理或覆盖。展示应区分已检查未发现风险、未检查和依据不足。新分析没发现旧问题，不代表旧风险自动解决。

当前处理状态沿用：待确认、已确认待补充、已解决、不适用。非待确认须写结论；记录操作者、时间、前后状态与内容，使用修订号阻止并发覆盖。“产品确认怎么改”对应确认修改要求，不直接算已解决；修改完成后的结论需人工核对。

### 从对话人工新增风险

选择AI回复片段或整条回复 → 点击“添加为风险点” → 弹窗确认功能、标题、等级、描述、原文资料/位置/摘录、影响、建议及待确认问题 → 确认入库为待确认。

取消不写入；重复提交同次操作只新增一次。保存会话、消息引用、操作者和时间。聊天内容是线索，不冒充原文证据。人工新增项独立存储并进入累计清单、筛选、处理和导出，不覆盖首次AI结果。

## 5. 对话与AI调用

Web → 平台后端 → 当前操作者个人AI API。用户不需要安装本机连接程序或启动CLI；管理员同样只能使用本人配置，不借用历史平台密钥或其他成员配置。以后按具体供应商协议增量接入，不预建空适配层。

平台保存自己的分析、对话及消息标识；供应商response_id可作诊断信息，不能替代平台历史或鉴权。

| 对话 | 上下文 |
| --- | --- |
| 需求分析对话 | 本次固定资料、功能风险结果、最新人工确认、本对话已完成历史和本轮问题 |
| 功能独立对话 | 对应功能的固定资料/风险、必要公共规则和确认、本功能历史与本轮问题 |
| 风险追问 | 属于功能对话，增加明确的风险引用，不另建历史 |

普通聊天只产出回答。自然语言聊天不强制输出报告JSON，不从“已解决”等用语自动执行写入。新增风险必须经过专门的人工确认接口。

当前不设置平台固定上下文字节上限，不静默裁剪资料；服务商实际上下文限制仍可能报错。长历史整理/检索为后续工作：必须保留完整可见历史和原始依据，明确每轮实际采用范围，不能用无来源摘要替代产品事实。

## 6. 后台、权限与错误

- 沿用项目权限，项目内共享分析及对话；每轮由发起人本人配置调用。
- 单次发送先持久化，再交独立Worker处理；同一对话同时一个活动轮次，UUID幂等和历史版本校验防重复计费/并发串话。
- 离开页面不取消已保存请求；返回后读取状态与历史。
- 仅本轮发起人可停止；停止接收/保存不等于上游立刻停止计费。
- 失败保留问题及错误，用户手动重试；不自动重发可能已计费请求。重试使用重试者本人配置。
- 执行前后重查账号/项目权限，外部等待前释放数据库事务；重启将可能已执行的RUNNING标为失败，不自动续算。
- 密钥后端加密保存，前端及日志不存密钥、原文或完整提示词。资料是不可信输入，不能扩大权限。Git仅固定读取白名单。

## 7. 清单导出

功能和处理状态均多选，组合生效，默认全选，显示实际导出数量；空结果不导出。分页不限制导出数量。跨分析导出保留每条来源分析以及功能名称、风险等级/描述、原文依据、影响、建议、产品确认和当前处理状态；人工新增项还保留会话来源。原型当前格式为Markdown。
