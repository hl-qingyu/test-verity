# UI控件规范

## 柔光问答主题

工作台、登录页和总原型共用 `frontend/src/soft-theme.css`。主题使用淡紫渐变背景、白色圆角卡片、紫色主操作、浅紫选中态与柔光弹窗。成功、警告和危险状态使用各自的语义颜色与文字。窄屏沿用工作台现有的侧栏、表格滚动与弹窗尺寸规则。

业务模块复用主题的文字、背景、边框与交互颜色变量。通过与完成等正向状态使用成功色，终端和图片预览使用深紫底色。

页面和弹窗使用短入场动效。概览数字以真实统计值为终点，辅助技术直接读取真实值。启用系统「减少动态效果」时，界面直接显示静态渐变及最终数值。

## 界面文案

常驻说明只保留用户判断和操作所需的信息：实际状态、数据范围、输入格式、计费、权限限制、未保存内容、不可恢复后果及下一步。删除重复的项目共享、历史留存、不会自动修改等通用说明；后台校验、事务、Worker、缓存和协议实现写入模块文档，不作为常驻页面注释。真正未接入的能力、读取限制和错误原因必须如实显示。

同一提醒在相关操作处说明一次，避免页头、侧栏、正文和弹窗反复出现。计数为0时不额外展示“没有问题”类提示；有问题时明确问题数量和处理入口。指标定义保留在按需展开的说明中。精简文案不改变业务状态、菜单、字段、权限或操作流程，修改时同步根总原型。

## 表单弹窗滚动

表单弹窗由正文容器承担纵向滚动，标题与底部操作栏保持可达；打开模态弹窗时锁住背景文档滚动。原型页面、GitHub/本地文件树、版本、资料、用例范围及附件候选等嵌入式选择清单随正文自然展开，避免在“弹窗正文 → 选择容器 → 清单”连续设置限高和滚动。共用规则位于 `frontend/src/dialog-scroll.css`，页面外文件树仍可独立限高。

下拉选项、代码/图片预览、二维表格、审核工作区的独立分栏及聊天记录保留自身必要滚动，不使用全局 `overflow: visible` 抹去其边界。窄屏核对横向溢出、长路径、键盘滚动、焦点与操作栏可达性。

2026-10-20登录提示：Form可通过validationMessage指定本表单校验文案，仍阻止无效提交并聚焦原错误字段，未指定时沿用通用提示。登录页统一为“账号或密码错误，请重新输入”，其他业务表单继续原文案与规则。

2026-10-20项目资料页头统一：需求资料、原型资料、用例管理的顶部操作按钮与左侧“标题＋说明”整体垂直居中，使用同一页头样式，避免原型页单独顶端对齐。760px及以下保持靠左，按钮区域按各页已确认的单行滚动／换行规则适配。

## 按原型开发，不得擅自简化（2026-10-14明确）

所有UI均须按照已确认原型开发，包括页面布局、尺寸与间距、控件外观、展开内容、弹窗及完整交互。禁止为省事、赶进度或“先实现功能”替换成简单控件、简化布局或省略状态；只实现功能、不还原原型，不算完成。

优先复用满足原型的主题组件；现有组件不满足时补齐外观与交互，不能反过来降低原型要求。浏览器语义底层和必须的系统窗口边界仍按下文执行，不允许据此使用未主题化的可见业务控件。

开发前逐项对照原型，交付前核验布局、尺寸、间距、按钮、下拉展开项、弹窗及正常/加载/空数据/失败/禁用/选中状态，并检查长文本、窄屏、键盘、焦点、遮挡和溢出。类型、测试、构建通过不能代替视觉对照；工具受限时明确列出未验证项，不声称完全符合原型。确需偏离原型，先列明具体差异并取得用户确认。

2026-09-14用户明确要求，适用于全部现有页面及后续开发。整体外观以已确认总HTML原型为准；菜单、功能、字段和权限不因控件统一而改变。

## 共用控件

| 场景 | 使用方式 |
| --- | --- |
| 单选下拉 | `FormSelect`或`Select`，按钮和展开选项都使用主题样式；禁止可见原生select菜单 |
| 自由输入与常用建议 | `FormSelect editable`，保留任意合法输入；禁止浏览器datalist弹出列表 |
| 按钮 | 共用button基础样式及primary、ghost、small、danger等已有变体；图标按钮有可读名称和焦点 |
| 业务确认/编辑弹窗 | 复用CaseDialog或已有主题dialog；禁止alert、confirm、prompt |
| 表单 | 使用Form，保留必填、格式与长度校验，以应用内文字显示错误并聚焦字段；禁止reportValidity气泡 |
| 文件选择入口 | FilePicker，主题按钮触发隐藏文件输入；保留多选、取消和重复选择同一文件 |
| 分页跳转 | PageJump，沿用总原型“跳至＋确定”，支持回车、整数及范围校验、行内错误、禁用和焦点保留；不得触发外层业务表单提交 |

Select的option子节点仅作为选项配置读取，不挂载为原生菜单。组件支持受控value与defaultValue；name通过隐藏表单字段提交，数字ID转为字符串后由原调用方解析。字段值、权限、请求协议与业务规则不可因换控件而丢失。

## 弹窗操作栏

- 底部操作栏主/次按钮上下居中、同一行高度一致，组内间距8px，按钮不单独添加上边距。常规操作按钮至少40px高；图标、分页或正文内的小按钮保留原变体。
- 操作组负责与正文的间距；独立表单提交按钮可保留自身间距，不把它施加到弹窗页脚。长文案与窄屏允许组内换行，不挤出弹窗或覆盖正文。

## 交互与无障碍

- 下拉箭头固定在控件右侧并垂直居中，使用不受字体基线影响的图形，不用文字字符模拟；预留箭头空间，长文本不挤压箭头。
- 下拉使用顶层popover避免被表格/对话框滚动区域裁剪，使用白底、圆角及浅紫悬停和选中态。选项不显示勾选符号，长列表可滚动，长文本可换行。
- 保留方向键、Home/End、Enter/空格、Esc/Tab；跳过禁用项，选择/关闭后合理恢复焦点。Esc先收起下拉，不误关编辑弹窗。
- 禁用控件不可鼠标或键盘选取；空选项不等于业务成功，无可选项明确提示。按钮具有名称，label关联输入，不仅靠颜色表达状态。
- 缩放、窄屏和页面滚动不能让弹层错位或遮挡关键操作；分页等已确认单行布局不得被全宽下拉撑成两行。
- 使用button、dialog、popover等浏览器语义底层是允许的，可见界面必须经过统一设计，不自行仿造其无障碍语义。

## 系统边界

文件选择窗口、浏览器权限确认、刷新/关闭页面的未保存保护由系统控制，无法替换为页面组件。保留这些能力保护数据；页面内的按钮、业务确认与导航离开提示仍统一使用应用UI。嵌入第三方原型自身的控件由原站控制，不伪称已改造。

## 验证与后续执行

`npm test`包含UI规范防线：禁止源码引入原生select/datalist、绕过Form或调用浏览器业务提示；覆盖表单值保留、禁用选项、自由文本和校验阻断。另运行check与build，涉及请求继续运行公共请求回归。视觉检查必须核对展开后的选项、弹窗内定位、窄屏和焦点；不能只看收起的外框，工具受限时明确说明未完成视觉验收。

本轮统一范围：27处原生下拉（账号、AI服务、GitHub、项目、用例、资料链接、Excel切表）、用例类型建议、两处文件按钮及14处表单。既有应用内业务弹窗和按钮样式沿用。总HTML动态渲染的原生选择/建议节点统一由主题适配层提供可见控件，保留原ID、字段及事件契约。
