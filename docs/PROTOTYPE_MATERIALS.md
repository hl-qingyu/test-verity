## 正式模块边界与接口

调用链：Prototypes / PrototypeEditor / PrototypeLinkPreview → prototypeApi → api/http → prototypes/router → prototypes/service → documents公开权限/存储与github客户端。需求图片选取通过documents?include_prototypes=true获取，两类列表默认隔离，文件预览每次鉴权。原型图片不支持HTML/ZIP或其他代码上传。

接口前缀 /api/projects/{project_id}/prototypes：

| 方法与路径 | 功能 |
| --- | --- |
| GET 空路径 | 分组、来源与共享资料修订号 |
| GET /options | 本人连接及与项目仓库的交集，不返回凭据 |
| POST /groups、PATCH /groups/{id} | 创建/改名原型分组 |
| POST /move、POST /reorder | 移组、同组上下排序 |
| POST /upload | 原始图片流，复用文件校验、上传UUID和私有存储 |
| POST /scope | 验证本人授权，固定提交后读取指定目录文件清单 |
| POST 空路径、PATCH /{source_id} | 创建/编辑实时来源配置；保存前重验提交与文件 |
| POST /{source_id}/check | 进入资料时核实当前分支提交，提醒并保存最近成功检查元数据 |

GitHub在原固定白名单中新增GET /repos/{owner}/{repo}/git/commits/{sha}和GET /repos/{owner}/{repo}/git/trees/{sha}?recursive=1，仅接受校验过的仓库名称与40位SHA；不跟随重定向或返回内容中的URL。一次读取固定提交和树，忽略符号链接/子模块，不跨目录前缀。原型读取不设置文件数量、文件size或树响应字节上限；递归树截断时按目录补读，不能完整读取则明确失败。仅支持HTML/CSS/JS/TS/JSX/TSX/Vue/JSON/MD/SVG原型文件元数据，源码不展示、不执行、不上传模型。不把截断列表称完整。

保存表单携带资料revision及读取时commit，分支提前更新返回409并要求重读；所选文件消失返回明确错误，不自动扩大范围。更新检查不改配置修订号，不生成资料v1/v2；重复网络检查按已观察检查时间校验，避免迟到响应覆盖更新结果。图片保留独立文件版本，实时资料无法调用图片更新入口。GitHub没有可用本人连接时明确提示配置，不能借用创建人的凭据。

链接仅由浏览器在用户点击时访问HTTP/HTTPS地址；iframe使用allow-scripts/allow-same-origin沙盒且不允许顶层导航，不发送Referer，本站同源链接只提供新窗口。不能可靠从跨域iframe事件判定成功或失败，所以不伪造“加载成功”状态。正式网页内容/截图快照采集和AI处理仍未实施。

文件存储失败会明确报错；多图顺序上传，保留已成功部分并显示未完成数量，不称整批成功。前端检查图片解码，后端复用扩展名及文件签名校验；不声称后端已实现完整图像解码。所有表和新增字段有中文真实COMMENT。

## 页面与流程

- 入口在“项目资料”分组，顺序为需求资料 → 原型资料 → 用例管理；其他菜单保留。
- 复用总原型已有资料左右布局、弹窗、自定义下拉、图片放大和版本来源对照。左侧按组展示资料，右侧查看说明和内容。
- 三种添加方式：从 GitHub 添加、添加链接、上传图片。资料字段包括名称、分组、页面/交互说明；图片名称可空，默认使用文件名，多图可加统一名称前缀。
- 分组支持创建空组、改名；资料支持移组、组内上下排序、更新版本及历史查看。分组与功能模块分类独立，不新增删除能力。
- 更新版本新增资料版本，历史只读。整理分组不覆盖原文，历史需求/任务来源不自动切换至最新版。
- “查看三类示例”仅在当前项目幂等追加虚构代码、链接和内置图片，不清空已有资料、不创建 GitHub 连接或扩大授权。

## GitHub 代码

1. 选择本人已配置的 GitHub 连接。
2. 仓库选项为“该连接已授权仓库”与“当前项目已关联 GitHub 仓库”的交集。不使用他人的连接，不将项目可见性视为 GitHub 访问权限。
3. 选择分支 / Tag / 提交，填写目标版本和仓库内原型目录或文件路径。提交使用完整40位编号；路径不允许绝对路径、上级目录、反斜线或空路径段。
4. 读取后固定提交、仅展示文件清单，勾选需要的文件后保存。修改连接、仓库、版本或目录后清空读取结果，需重新读取和选择。
5. 本轮按钮明确为“读取示例文件”：展示内置文件名清单，不声称获取了目标仓库实际代码。提供权限不足、版本不存在、目录为空、限流、超时的失败演示，失败不新增资料。

保存范围包括仓库、原始版本选择、固定提交、目录和文件列表；源码不在页面展示，不运行脚本。正式读取须按架构接入固定只读白名单，后端重验当前用户/项目/连接/仓库权限；本轮未新增接口，不提供任意 Git 命令、远端写入或网页抓取。

## 链接与图片

- 链接接受 HTTP/HTTPS，不接受脚本协议、本地路径或 URL 用户名密码。用户可点击加载内嵌预览或在新窗口打开；新窗口采用 noopener/noreferrer。进入资料页不自动访问地址，不保存访问密码。
- 链接资料版本只固定地址及说明，不固定网页内容。页面明确“未保存页面快照”；后续分析需补充截图或固定代码，不以链接存在冒充已获取页面证据。
- 图片支持 PNG/JPG/JPEG/WEBP、多选、继续追加和拖入；校验非空、扩展名及浏览器能实际解码后再登记。原型使用临时对象 URL 预览，刷新后需重新选择，不声称持久存储已实现。
- 更新图片版本仅接受一张。复用图片原尺寸、适应窗口、缩放和滚动查看。

## 需求来源

- 需求分析选择资料时分别列出需求资料和原型资料，保留资料用途选择。原型资料使用既有“原型图”内部用途值，显示名称为原型资料。
- 原型资料页不关联验收点。一份原型可覆盖多个功能；需求分析结合资料提炼独立验收点，具体页面/状态/交互的依据归属验收点详情，支持多处来源并保留快照。
- 关联引起业务版本变化并保留历史；已确认验收点转待审核，待补充仍保持待补充。关联本身不表示业务已审核或测试通过。
- 来源对照支持代码、图片和链接记录。任务范围快照同时保留代码提交和所选文件；更新原型资料不改写旧快照。链接来源继续标明无页面快照。
- 本轮不调用 AI 或 Skill。原有内置模拟任务仅用于演示，真实资料不会生成虚构分析结论。
