## 已确认业务规则

1. 覆盖需求分析、代码分析、变更分析、用例生成、用例分析五类记录，包括失败、取消、已完成、待开始及导入记录。先提供单条删除，不增加批量清空、回收站或恢复入口。
2. 采用逻辑删除，记录删除时间和操作人。保留原始输入、报告、对话、人工处理、应用审计与重试关联，不清理原文件或远端内容，不回滚已入库用例及其设计审核、测试记录。
3. 普通项目成员可删除本人发起／导入的记录；项目负责人和平台管理员可删除该项目全部记录。所有操作先核对当前项目访问权限，再在服务层检查删除权限。
4. 分析、批次、对话或应用入库任务处于排队／执行中时禁止删除；明确提示先取消或等待结束。未开始的 PREPARED 记录允许删除，删除本身不启动任务、不自动取消或重试。
5. 删除后从模块列表、项目概览和 AI 结果验收汇总中排除，统计分子分母同步重算。原有独立历史记录和已固定的来源快照不改写；不再允许把已删除记录选作新分析的来源或基准。
6. 已删除记录禁止通过原详情、导出、处理、重试、对话及应用接口继续操作。已有记录中保存的来源快照与关联 ID 保留；未固定输入的后续准备若必须读取已删除基准，明确拦截并提示重新选择，不用当前内容替代历史输入。
7. 删除影响整个项目的共享记录视图。主题确认弹窗说明记录名称、删除范围、历史保留与统计影响；提交中防止重复点击，失败留在当前记录并展示安全错误。成功后清除当前详情及对话状态，刷新列表并处理最后一页为空的情况。

## 交付验收

- 覆盖本人／他人、负责人／管理员、跨项目、权限撤销、重复提交、版本冲突，以及执行／对话／应用和删除并发的服务测试；真实数据库测试使用事务回滚，不删除用户真实记录。
- 确认六类持久化对象和全部读取／写入入口无遗漏；已删除记录不重新入队，重试后代保留，已入库用例和固定历史快照不变，概览及全部／单项目验收汇总口径一致。
- 前端验证确认／取消、提交失败、最后一条／最后一页、迟到轮询不回填、项目及记录切换、键盘焦点与窄屏；对照两份总原型完成视觉检查。
- 运行后端架构、数据库注释、Alembic 一致性和对应业务测试，以及前端请求回归、UI 检查、类型／格式／生产构建。

逻辑删除不会释放原始资料、报告及对话占用的存储空间；从验收汇总排除记录会改变汇总结果。彻底清理、恢复或不同统计保留规则需另行明确，不由本方案默认加入。

需求报告可能由多位用户的相同输入／结果幂等关联；普通成员须同时拥有这些关联记录的删除权限，统一删除他人关联任务由项目负责人或管理员执行。独立重试后代不联动删除。

实现使用 `modules/projects/record_deletion.py` 统一删除规则，原业务 getter／候选入口校验 deleted_at；读取列表、概览、验收使用 SQL 条件过滤。历史请求幂等索引保留，命中已删记录返回 404，不重新收费执行。原型只操作浏览器合成数据，将演示原件保存在 `deletedAnalysisRecords`；此演示结构不对应新增数据库表。
