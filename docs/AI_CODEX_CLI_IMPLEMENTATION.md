# API 与 Codex CLI 实施契约

## 业务执行

五类分析通过统一 AI 客户端选择 Responses API 或 Codex CLI，使用固定输入、Skill 快照和调用方式。分析结果经各模块结构、权限、来源及引用检查。收费调用由业务入口触发，平台恢复只交付已保存的结果。原生 CLI 可在一次任务会话内多轮读取资料。

CLI 在后端 Windows 上运行，使用已配置的 Codex 可执行文件，版本用于显示和诊断。部署需具备 ConPTY 和 Node.js 24 及以上版本。连接测试启用固定文字和一次转发限制。实际模型服务及个人配置需在有授权的环境中验收。

## 只读工作区

私有目录绑定当前用户、项目、记录及执行。任务保存固定输入与指令，进程通过标准 MCP filesystem 的只读模式访问当前工作区。终端运行配置禁用 shell、联网、插件、Apps 和 hooks。输入中的指令属于业务数据。PDF 通过 Responses API 分析。

结构化 reading-v2 目录供新的用例生成、用例分析、需求风险和 v3 代码及变更任务使用。按资料、文件或用例组织阅读目录，长文本按行优先切分，内嵌图片还原字节通过 read_media_file 读取。原 reading-v1 会话仍使用按消息排列的阅读文件。恢复前用认证加密清单核对原件和目录，之后复用已有版本。

变更分析 v3 先向模型提供差异和代码清单，并提供完整双侧只读文件。其余接入模块按任务索引读取本次固定资料。两种读取布局均保留业务输入中的来源和引用标识。

## 历史对话与连接

五类分析在历史对话内使用共用 xterm。重连按 cursor 补新增 ANSI 帧，并按已保存的行列数和 resize 事件还原画面。首次恢复后显示最新画面。缓存限当前登录和项目的页面内存，按实际执行区分。恢复会话根据原生线程标识绑定历史，用户发起新问题后继续分析。

通用终端入口在 /api/projects/{project_id}/analysis-terminal/{kind}/{record_id} 下。用例生成的旧终端 URL 可供历史客户端使用，已完成的候选轮次继续通过原审核入库流程。项目成员可以按模块权限查阅报告，终端写入校验本次执行发起人。

## 调度和结果恢复

Worker 持有同一 PostgreSQL 会话的咨询锁。任务领取遵守全局、每用户及同凭据并发预算。数据库断开时暂停领取，CLI 进程可继续执行。完整结果先按调用预留加密原子保存，后端恢复后重新检查身份、资料权限和配置，再交付结果。仅有开始标记的任务保留中断状态。
